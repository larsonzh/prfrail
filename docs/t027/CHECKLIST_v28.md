## 八、跨片协作纪律

| 要素 | 内容 |
|---|---|
| 载体表 | ①⑤⑥⑦ 用 `deep-reasoner` / `independent-reviewer`（只读）；②③⑧ 用 `prfrail-implementer` / `prfrail-tester` / `prfrail-documenter`（可写）；禁止 `prfrail-tester` 跑审查层；批量辅助必须是 `deep-reasoner` |
| 派单表机械读取 | 停点回执每行 `agentName` 必须从 `transcript.arguments.agentName` 逐字读取，附脚本 stdout 原文 |
| R2.1 | 每次 `runSubagent` 必须同时含 `agentName` 与 `model` |
| 提交信息 | 含非 ASCII 时必须 `git commit -F <UTF-8 文件>`；纯 ASCII 用 `-m` |
| 可独立核对与不可独立核对 | 枚举、事实比对、引用点清单属前者，模型错误不构成作废；判断、结论、审查意见属后者，模型错误必须重做 |
| ⑥ 先于 ⑦ | ⑥ 必须在 ⑦ 之前；重派 ⑥ 且文档有变更时 ⑦ 结论须重估 |
| 临时件 | 一律 `tmp/<切片ID>/`；只增不删；仅第八阶段收尾清理；逐件回读证明 |
| 长命令重定向 | 不用 `>`；用 `Tee-Object` 或 `cmd /c "..."` |
| 门禁 | 中间环节 `--all --skip-base`；提交前全绿 |
| 纪律 E | 先精确 `git add`，再 `--scope=index`；报 `G6-1 scanned N` 且 N 大于 0 |
| 纪律 F | 示例文本与措辞规范冲突时按规范执行，但须回执登记冲突 |
| 批量辅助 | 只用 `GLM-5.3-Flash (glm)`；至少 2 次，建议 3 到 4 次 |
| 审查方只读 | ⑦ 不得创建、修改、删除任何文件（含 `tmp/`）；来源写法为读取主控落盘的路径 |
| 纪律 A | 停点回执 CI 取证所需 push 视为片内必要动作；用户明确不 push 时从其措辞；不得作先例 |
| 纪律 B | 证据缺口须写丢失什么、什么未丢，并明写未主张缺口已消除 |
| 纪律 C | 枚举优先于推导；遇总量减已知等于差值时多跑一条枚举命令 |
| 纪律 D | 白名单政策优先于授权数量，但不得据此判越权或拒执行 |

P38 新增教训：单个子代理单次输出有硬上限；要求长文档时必须先分批（每批不超过 10,000 字符、每批单主题），并在派单文本写明禁止自重启与 `SELF-RESTART-ABORT` 逃生标记。
