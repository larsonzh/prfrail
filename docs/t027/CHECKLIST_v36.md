## 七、起跑与步骤 0 通则

1. 核锚点 → 步骤 0：登记本片台账（`R/D = 0` 基线、临时件落点 `tmp/<切片ID>/`）、落 `input-list.md` 与 `freedom-list.md`。
2. 每个修复切片必须给出**回归测试**，并把「未执行测试/lint」显式登记。
3. ⑨ 三作用域全绿 + `SELFTEST 697/697` + `go build/vet/test ./...` 全绿，方可提交。
4. 模型绑定（硬约束）：①⑤ `deep-reasoner` + `DeepSeek V4 Pro (deepseek)`；②③⑧ `DeepSeek V4.1 Flash (deepseek)`；⑥ `independent-reviewer` + `MAI-Code-1.1-Flash (copilot)`；⑦ `independent-reviewer` + `GPT-5.3-Codex (copilot)`；战略回看轮 1/3 `independent-reviewer` + `GPT-6.1 Sol (copilot)`；批量辅助 `deep-reasoner` + `GLM-5.3-Flash (glm)`。**每次 `runSubagent` 必须同时传 `agentName` 与 `model`**。
5. **执行节奏纪律**：常规不停——④ 全绿 ⇒ 直接派 ⑤；⑤/⑥/⑦ 报 Medium+ ⇒ 修复后原位重跑该环；**⑩ 才是唯一常规停点**。
6. 跨版本/跨平台排查：CI 与本机分歧先查工具链版本与构建标签覆盖；交叉构建后 `go env GOOS GOARCH` 复核；删「本机未使用」符号前至少一次对向 `GOOS` 的 `go vet`。
7. 批量辅助：每片实派 `deep-reasoner` + `GLM-5.3-Flash (glm)` **≥ 2 次**（策略与输出上限见 §八）。
8. 主控模型策略：默认 `DeepSeek V4.1 Flash`；遇底层并发/状态机/句柄类复杂片、单份超 10,000 字符设计文档、大量 CI 日志深度根因分析、或 Flash 连续 2 次行为漂移时切换 Pro；**任何降级须按 OB-37 元规则独立登记**。
9. **角色载体不可替代**：② 必须 `prfrail-implementer`、③ 必须 `prfrail-tester` 派单；主控只做编排、落盘、门禁与回执，**不得代写产品代码或测试**。
10. **起跑消息即工件**：步骤 0 必须把用户起跑消息原文落盘为 `docs/validation/evidence/<切片ID>/00-briefing.md`，并入 `MANIFEST.md` 与 `SHA256SUMS.txt`，同时在 `artifacts` 围栏声明；缺此件不得进入 ①。
11. **线性化点纪律**：涉及持久化状态机时「持久化成功」必须是线性化点，内存 CAS 只作同进程快速拒绝缓存；须写明「取额成功 ⟺ 标记已在盘」并配正向红测。
12. **证据包与围栏同步纪律**：新增证据载荷必须同轮补 `MANIFEST.md` 条目、重算 `SHA256SUMS.txt`、在 `artifacts` 围栏补行；任缺其一都会被 `G8-b` 或 `G5(d)` 拦下。
13. **审查方归档纪律**：⑤⑥⑦ 产出必须逐字原文归档；主控不得按要点重建；确需摘要时另行成文件并在围栏外披露。
14. **装配验证片纪律**：断言必须落在可证伪的机械判据上；常量恒等须显式声明非哨兵；报告必须声明生产代码是否零改动；某层未支持的能力不得被读作已支持。

## 八、跨片协作纪律（起跑消息必须落实）

|---|---|

| 门禁执行 | 中间环节用 `--all --skip-base`；提交前必须全绿 |
| 纪律 E · index 作用域顺序 | 先精确 `git add` → 再跑 `--scope=index`；回执须报 `G6-1 scanned N` 且 N 大于 0 |

| 纪律 I–N | 判定词闭集 / 审查语义 / 持久化优先 / 三方自洽与围栏同步 / 归档即原文 / 机械判据与非哨兵声明（分别见 §七 第 11–14 条） |
| **纪律 O · 输出长度防御** | 单次输出不得超过 10,000 字符；超限前按 §七 计划分批；禁止自重启；按需读取而非全量载入；触发止损条件立即停并报告 |
| **纪律 P · 主控模型切换触发** | 见 §七 第 8 条：底层并发/状态机/句柄、超长设计文档、大量 CI 日志根因、Flash 连续 2 次漂移 ⇒ 切 Pro；降级按 OB-37 登记 |
| **纪律 Q · 批量辅助输出上限** | 派单须写明字符上限；回执须报实得字符；超上限但完整者登记为计量事实（不属 §七 止损范围）；平台实测 ≥ 10,190 字符可作上限校准依据 |
| **纪律 R · 时态滞后批量清账** | 台账与事实不一致（GAP-12 / GAP-19 / GAP-24 类）走一次性清账片，以代码与提交为事实源；不得逐行打补丁式修补 |
| **纪律 S · 会话长度与压缩纪律** | 上下文达到 100K 或出现「历史压缩」提示 ⇒ 立即结束当前片；一个会话只跑一个 L 档切片；压缩会淘汰早期硬性停点与授权纪律并诱发漂移（D-02 即此类） |

**GLM 批量辅助策略**：`GLM-5.3-Flash (glm)` 资源充足，「≥ 2 次」仅是下限，机械核对、长文档摘录、双语镜像检查、派单草案、日志提取应尽量外派；禁止复杂判断与择优；每次实派计入 ⑩ 的成本与计量（输出上限见纪律 Q）。

**P46 新增教训（v36 起）**：① **评估类切片在 ⑨ 全绿后必须停在 ⑩ 等授权**——D-02 的根因就是把它当成实施类流水线直接提交；② **§7 读数自指**：改正文会移动六形状读数，须「先改正文、最后统一回填 §7、再复算至稳定」；③ **门禁判据会拦下措辞**：`G2` 拦占位词、`G6-4` 拦计数类字面（占位词不得残留），处置方式是改词，不得扩白名单。

## 九、清单元规则

**引用时用首句引文，不用「第 N 条」。**

| 规则（首句引文） | 内容 |
|---|---|
| 「每 2 个切片 / 待裁定变化 / 准则升版 / 队列变化 / 用户要求 / 锚点 ≥2 不符 ⇒ 重新生成」 | 触发重新生成的时机 |
| 「待裁定项必须逐项列名」 | §六 必须逐项列名 |
| 「队列项必须给出六要素」 | 标识 / 内含 / 规模分级 / ⑦ 额度 / 依赖 / 边界 |
| 「规则义务 ≠ 门禁义务」 | 不把规则文本当机械判据 |
| 「禁物理时钟断言」 | 观察项等条款以事件为触发，不以「N 个月后」为触发 |
| 「提交前门禁绿」 | 硬门 |
| 「派单表 agentName 机械读取」 | 从 `transcript.arguments.agentName` 逐字读取 |
| 「治理片不回写 DEV_PLAN」 | 准则治理切片的权威台账 = 附录 C.0–C.0x |
| 「片名一经进台账即不改」 | 片名稳定 |
| 「授权数量与政策冲突时以政策为准」 | 不得以此判定越权或拒绝执行 |
| 「同一事实只在一处描述」 | 正文或指针择一 |
| 「主控登记文本可措辞补全；审查方原文必须逐字」 | 两侧标准不同 |
| 「事实错误独立于设计决策」 | 台账与报告互斥属事实错误，不等设计裁定 |

| 「执行载体偏离＝最高级独立性降级」 | 须登记 D 项并附独立影响评估 |
| 「机械判据优于见证性陈述」 | 零模型/零副作用类断言须可证伪；常量恒等标注非哨兵 |
| 「并发断言须覆盖存活与释放」 | 除失败面外须断言赢家存活、槽位释放后可重发 |
| 「层边界不得扩大读法」 | 某层未支持的能力必须显式声明 |
| 「评估类切片 ⑨ 后必停 ⑩」 | **v36 新增**：评估类无实现对象，⑨ 全绿后停在 ⑩ 等同轮授权，禁止自行 commit/push |

| 「压缩即结片」 | **v36 新增**：上下文 100K 或出现压缩提示 ⇒ 立即结束当前片，一会话只跑一个 L 档切片 |
