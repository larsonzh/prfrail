### 2.2 不可控项（必须人工先设，主控无法自设）

`runSubagent` 只接受 `prompt` / `description` / `agentName` / `model` 四个参数，**没有** `budgetTokens`、`reasoning_effort`、温度等旋钮。因此：

- 8000 token 输出预算与 MAI 的 `high` 档**必须在启动前由人工在模型设置中设定**；
- 主控只能**观察**其效果（输出是否被截断、推理是否达到预期深度），并在报告中如实记录；
- 若人工未设定，主控**不得**在报告中声称"已按 high 档执行"。

### 2.3 模型标识解析与回落梯（修正 v1）

Haiku/MAI 属 **Copilot 原生模型**（非第三方扩展），故 v1 的"用扩展显示名"不成立。回落梯改为：

1. `"Claude Haiku 4.5 (anthropic)"` → 2. `"claude-haiku-4.5"` → 3. `"Claude Haiku 4.5 (copilot)"`
4. 三者全失败 → **重度失败**，④ 立即切回 Codex 全量终审并记录（§6.2）。

MAI 同理：`"MAI-Code-1.1-Flash (microsoft)"` → `"mai-code-1.1-flash"` → `"MAI-Code-1.1-Flash (copilot)"`。标识证据以上表 ID 为准。

**实测结论（2026-09-15，探针 1/2）**：`Claude Haiku 4.5 (anthropic)` 与 `(microsoft)` **不在 `runSubagent` 白名单**——Copilot 服务模型的 vendor 串统一为 **`(copilot)`**（工具回显的权威清单包含 `Claude Haiku 4.5 (copilot)` 与 `MAI-Code-1.1-Flash (copilot)`）。因此回落梯首级修正为 `(copilot)`，**两个标识已解析、无需再耗额度**：

- ④a：`runSubagent(agentName="quick-verifier", model="Claude Haiku 4.5 (copilot)")`
- ④b：`runSubagent(agentName="independent-reviewer", model="MAI-Code-1.1-Flash (copilot)")`
- 兼注意事项：工具回显清单中含禁止模型（Gemini 3.x / GPT-5.6 Luna / Terra / Sol / GPT-5.4），**仍按 §10.1 执行白名单**，不得误用。

## 3. 六步协议（①②③ 不变，新增两条硬要求）

### ① V4 Pro 前置分析（Max，必须调用）

A6 虽不在强制调用清单，但涉及进程治理、崩溃路径与证据采集，**必须调用**。要求输出：

1. 进程生命周期状态机（start / stop / timeout / tree kill / cancel 的完整转移，含非法转移）；
2. 崩溃窗口遍历（所有"进程中间状态 + 崩溃"组合及其恢复路径，标明可证 / 不可证）；
3. 证据采集缺失模式（logs / events / manifest / diff / usage 各自缺失的场景与 fail-close 口径）；
4. Windows 进程树与 Job Object 语义差异，及 Unix（process group / setsid）对应差异；
5. guard 与隔离 workspace 的生命周期边界（谁拥有停止权、租约与接管）。

### ② Flash 实现（High）

代码 + 测试 + 双语文档同步落地；§3.6 四条纪律（单轮单改 / 门禁即时收口 / 不自行扩范围 / 变更最小化）严格执行。

**新增硬要求 H1：每个新测试都必须做变异检验。**
方法：去掉被测守卫 / 条件 / 循环，确认该测试**变红**；不变红即视为无效测试，必须重写。
留痕：变异项、期望结果、实际结果写入 A6 报告；源码必须按哈希校验还原（备份只放 `tmp/` 并在验证后删除）。

### ③ V4 Pro 预审（Max）

核对实现是否偏离 ① 结论，重点构造：进程崩溃窗口反例、取消竞态反例（timeout 与 cancel 同时到达）、进程树泄漏反例、证据缺失反例。
**闭环**：所有 Medium 及以上必须整改并**重跑 ③** 直至清零（第五章闭环纪律）。

## 4. ④ 两段式终审（试点核心）

### 4.1 独立性约束（不降级）

- 两位审查者均为**只读**：禁编辑、禁执行命令、禁写文件、禁再开子代理。
- 首轮输入保持**中性**：只给"需求 / 契约原句 + 完整 diff（含测试文件）+ 不变量清单"，**不给**主控的实现理由，**不预告**"已修复什么"。
- 重审轮（整改后）输入 = 该轮**修复 delta** + 原始发现清单，并**明示这是重审**（此为例外，可给上下文）。
- 审查者必须声明"我无法验证的部分"（工具/输入限制）。

### 4.2 ④a Claude Haiku 4.5 — 机械覆盖面扫描

- **职责**：diff vs 契约文本逐句对账；转移表 / schema / 夹具计数一致；编码与行尾（`.md` BOM+LF、`.go/.json/.js` 无 BOM+LF）；命名与哨兵一致；明显漏测与 TODO 残留。
- **输出格式（硬性，A2）**：`FILE:LINE | 类别 | 一句话描述`，**每条一行**；总数 ≤ 25 条；条目总数必须显式给出；**禁止**散文、**禁止**严重度判定、**禁止**给通过/不通过结论。
- **定位**：只是线索，不构成审查结论。
- **规模阈值**：diff 超 1200 行时按文件分组，最多 2 次调用（计入 ④a 调用数）。
- **空扫描**：记 0 条并**标注可疑**（不得读作"通过"）。
- **截断处理**：输出被截断（受 8000 预算所限）即该次扫描**无效**，收窄输入重发一次；仍截断 → 计入轻度失败并记录。

### 4.3 ④b MAI-Code-1.1-Flash — 路径推理面审查

- **职责**：不变量可证伪性、崩溃窗口与幂等、状态机可达性、信任边界与反例构造。
- **输入**：完整 diff（含测试）+ 契约原句 + Haiku 清单 + V4 Pro 预审发现清单（**置于附录区并标注"完成独立扫描后再读"**，防锚定，M4）。
- **输出契约与 Codex 完全一致**：
  - Section A：`RE-REVIEW: PASS` 或 `RE-REVIEW: FINDINGS`
  - Section B：`SEVERITY | file:line | 被违反的句子（引用） | 最小修复`
  - Section C：逐条证据与推理
  - Section D：**可证伪性审计（硬性）**——逐项给出"若删掉某守卫，哪个测试会红 / 不会红"，并列出它认为**无测试覆盖**的不变量
  - Section E：**"我无法验证的部分" + "什么会推翻我的 PASS"**（防橡皮图章，A1）
- **Section D 需被抽查（A11）**：主控必须从 Section D 中**随机抽取 1–2 条**"删掉守卫 X → 测试 Y 变红"的声明，并**实际执行变异检验**；若声明与实际不符，则该审计整体可信度降级，并作为试点结论的**负向信号**记录（MAI 的声明与我的测试同样不能自证）。抽查项、期望结果、实际结果均写入报告。
- **独立发现优先**：清单只作参考，**必须独立扫描 diff**；报告须分别给出"独立发现项"、"与清单重叠项"。
- **锚定信号（A-D3）**：若连续两轮"独立发现项 = 0"且清单非空，记录为锚定信号；必要时升级为**两调用分离方案**（先独立扫描 → 再对账）。
- **闭环**：所有 Medium 及以上必须修复并**重跑 MAI 复审**直至无 Medium+。

### 4.4 ③ 与 ④ 的记账分离

V4 Pro 预审发现的问题**不计入 MAI 发现**；报告中必须分别列出 ③ 总数、④ 独立发现数、两者交集、以及"MAI 是否漏掉 ③ 已发现项"。

### 4.5 调用异常处理（A3）

单次 ④ 调用超过 10 分钟无输出，或输出明显截断 / 缺 `file:line` → 收窄输入重发 1 次；再失败即计入"组合可用性失败"，作为 §6 回退级别判定依据。

## 7. ⑤ 原生验证

### 7.1 标准门禁（照常，不可跳过）

`gofmt -l` 空；`go build ./...`；`go vet ./...`；`go test -count=1 ./...` 全绿；契约夹具 `npm test`；改动文件逐字节编码/行尾校验。

### 7.2 A6 专项原生验证（stub-only，不依赖模型判断）

1. **进程树泄漏检测**：启动 stub CLI 后 kill 父进程，确认全部子进程终止。
   证据形式（A5）：停止后枚举存活 PID 集合为空 + guard 停机证据哈希入事件，不留"人工观察"式结论。
2. **超时边界注入**：在 timeout 临界点附近反复触发，确认无竞态。
3. **取消竞态复现**：cancel 与 timeout 同时到达，确认状态转移唯一且可复现。
4. **崩溃注入**：start / stop / evidence 采集各阶段注入崩溃，确认恢复路径可证。

### 7.3 工程约束（A4，避免 CI 抖动与假失败）

- Windows 单调时钟粒度约 15.6ms → 超时/取消断言必须用**容差**（如 ±50ms 或按 tick），**禁止**精确等值断言；
- 高频循环注入（"反复触发"）默认 **20 轮**、可配，且**不得**进入默认 `go test ./...` 路径（用 `-run` 显式选择或 build tag），以免 CI 抖动；CI 三步门禁仍必须全绿；
- 所有专项验证必须**可重复**：给出确切命令与预期输出。

## 9. 成功判据（先定后测，修正 v1 的判据 b）

| 判据 | 标准 |
|---|---|
| **(a) 无逃逸** | 无 Medium+ 逃逸到 ⑤ / CI / 后续切片 |

- (a)(b)(c) 全满足 → 可在 A7 之后的**常规切片**推广；
