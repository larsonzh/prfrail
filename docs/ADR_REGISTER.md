## 5. A7 Windows 发布耐久反证结论（ADR-013）

- **结论（2026-09-16，级别与前提必须一起读）**：在前提 **P = 进程级崩溃、无断电、单主机 Windows 11 / NTFS 本卷** 下——可见性与仲裁层 `proven`（P1–P5，构造性论证 + 观测）；**断电耐久 `unresolved`**（U1–U5）；**被证伪的断言集合 D1–D6 一律 `disproven`**（候选 C2/C3 的断电耐久仍 `unresolved` 并移交 B3）；**Windows 发布耐久保持 `unproven`**，`first-dispatch` 仍被拒绝；T027 仍 `BLOCKED / NOT IMPLEMENTED`，AT-23 未通过。**不得把可见性层的 `proven` 读成断电级保证。**
- **关键实测**：`record-linked` 与 `parent-synced` 在 kill 下观察等价（故 kill 不能证明目录项耐久，这是 A7 无法把任何候选升为 proven 的根因）；并发发布恒单赢家且“杀赢家不解锁二次派发”；**目录句柄 `FlushFileBuffers` 在非提权下可调用成功**（只读句柄被拒）——推翻 T004 以来“目录 Sync 不可用”的强表述；`MoveFileEx(MOVEFILE_WRITE_THROUGH)` 无提权可用、已存在目标映射 `fs.ErrExist`、目标被打开时拒绝覆盖。
- **候选排序（供 B3 注入）**：C2 与 C3 并列首选；C6 为契约修订后的结构性候选；C5 marker **不作为耐久机制**（作为“可见性+一致性”手段亦无增益，已证伪）。
- **级别口径与证据限制**：可见性与仲裁层（P1–P5）的 `proven` 带明确前提“进程级崩溃、无断电”，由构造性论证 + 可复现观测共同支撑；耐久类断言一律 `unresolved`。承载 E4/E6/E9/E10 的 `a7native` 实验**不进 CI**，属单主机证据，需在 Windows 主机手动重跑（`PROOFRAIL_A7_ROUNDS=20 go test -tags a7native -run TestA7Native ./internal/adapters/`）。
- **若 B3 日后采纳 C2/C3**：必须先按 `docs/CONTRACTS{,_EN}.md` §7「发布耐久等级与升级条件」完成协议先行修订（该冻结句已由 B3c 改写：Windows 目录项持久性“**不是平台常量**”，按（平台 × 前提）逐项判定）并经独立评审，**不得因 B3 通过就自动解锁** `unproven` 与 first-dispatch。
- **边界与移交**：断电类断言（候选 C2/C3 的落盘保证、C2 文档措辞歧义、本机存储栈 flush 语义、断电下目录项丢失有序、共享卷 fencing）全部交 B3；临时残留累积为 A7 发现项，不在本切片修。详见验证报告：[中文](validation/t027-windows-publication-durability.md) / [English](validation/t027-windows-publication-durability_EN.md)。
