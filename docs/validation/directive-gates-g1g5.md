## 1. 变更概要

- **基础 G1（状态标记一致性）脚本化**：四个机械子判据——(c) 状态符号 ∈ 台账自陈闭集 `⬜ / 🔄 / ✅ / ⛔`（`⏸` 仅限标题、只用于待评估项）；(d) 同名键的标题 ↔ 状态表符号相等，且状态表有行而标题无对应者判红；(e) 完成记录的键**经键绑定**后其标题必须为 `✅`——先按主键精确匹配，再按标题名中**反引号别名唯一匹配**（否则 `G1(e)` 对全部治理片恒为空判）；(f) **仅本次新增**的完成记录行不得含「进行中」/「In progress」/「待…定稿」类未完成措辞——即 `GATES-EDGE-COVERAGE` 实测缺陷的机械化形式。
- **四项记录态收口（如实声明，不机械化）**：① 标题仍 `⬜` 但实际已收尾且缺完成记录行（需片外事实知识）；② 标题已 `✅` 却无完成记录行（现行语料有 4 例 ⇒ 反向含义今日不可满足，故不判）；③ 摘要文字真实性；④ 停止态豁免（§1.6）的判定——四者由 ⑤⑥⑦ 与人工承担，已写进 §6.3 的 G1 行。
- **基础 G5（变更集契约）改为四字段机械派生**：废除「仓库外 JSON」的自证式要求——`stagedFiles` = 作用域变更集**减删除路径**、`declaredFiles` = 报告 `artifacts` 围栏中处置为 `repo` 的行 ∪ 报告自身路径、`evidenceRefs` = 新增台账行证据列的路径（**反引号与裸路径均识别**）、`addMode` = **派生标签**（git 不记录暂存方式 ⇒ 标签永不单独判红）。子判据：(d) **变更集 ⊆ 声明集**（反方向记 `INFO`；变更集不含报告 ⇒ `INFO`）；(e) 证据引用可解析；(f) index 作用域下**工作区干净**（porcelain 的 **Y 列**或 `??` 才判红，X 列已暂存正常）。**方向性不等 ⇒ FAIL（退出码 1）**；可选 `GATES_CHANGESET_JSON` 交叉比对不一致 ⇒ 用法错误（退出码 2）。
- **台账与脚本化状态**：「脚本化状态」段改为「不再有以 `SKIP` 打印的主规则」；`--list` 中 G1 / G5 变为 `scripted`；§12.5 对应缺口行翻转；附录 C.0x。
- **边界**：未改 §2.2 / §2.4 闭集、§5.2 矩阵、§7.5 数值与 G6–G8 判据本体；未动 CONTRACTS / schema / fixtures / workflows 与 `internal/**`；**未新增 ADR**（上限仍 25）。

## 5. 已知缺口与登记（裁定所称「§8」）

- **G1 的记录态收口边界**（四项，见 §1）：机械判据只覆盖「三处可锚定部分一致 + 新增完成记录无未完成措辞」；「标题陈旧但无完成记录行」与「标题已 `✅` 却无完成记录行」两类**仍需人工**（前者已实测存在于 `GATES-TIGHTEN` 的 P2，后者现行语料 4 例）。
- **G5 的自证风险**：三源（git / 报告围栏 / 台账证据列）互不依赖，`addMode` 只能以「未声明文件」与「工作区不洁」这两个可观测后果代理，**无法直接证明调用者用了 `git add -A`**（git 不记录暂存方式）——如实登记为该判据的强度上限。
- **G5(f) 的口径边界**：判的是「工作区 vs 索引」而不是「索引 vs HEAD」；后者属提交集核验，本片不覆盖。
- **① D6 六项的落点**：① 点名的一项（`✅` 标题却无完成记录行）与其余各项分别落在 §6.3 G1 行的四项记录态收口、G5 行的 `addMode` 派生标签说明、§5 的 G5 自证风险与 G5(f) 口径边界——**无一项被伪装成机械化**。
- **外部 JSON 交叉比对未进入 CI 路径**：CI 不带 `GATES_CHANGESET_JSON`，该分支只由自测覆盖。
- **本片范围内仍未闭合项**：无（上述三项为判据的**已声明边界**，非未完成项）。

### 8.1 为什么 ① 不可被下游环节替代（OB-95 的论证附件）

1. **⑤ 能抓到三项硬伤，靠的是「边界外发现」**：§4.2.1 第 3 条让 ⑤ 在实现落盘后逐条对照「方案 ↔ 代码」，本片三项硬伤都属「实现一变即可机械观测到的矛盾」——等号方向写成严格等价、证据列只认反引号、键绑定根本没有回退分支。**换一类缺陷就抓不到**：若方案缺陷是「实现形式正确但判据语义错误」（例如把 `INFO` 与 `FAIL` 的适用边界写反、把「新增行」与「全量行」的作用域写反），代码照方案实现、自测照方案断言，⑤ 大概率一并通过；此时 ⑦ 是唯一防线。
2. **⑦ 的命中率结构性偏低，有四个原因**：① 输入大（整片 diff + 切片定义 + 契约原句，几百至上万行，注意力必须分散）；② 一次性通过，没有 ① 的「先独立设计、再与主控方案对照」结构；③ 复审轮可附 ⑤ / ⑥ 清单，独立性被前轮结论锚定；④ 额度受限（1 + 3），专门做深度独立推导的预算不允许。
3. **三层防线的可靠性逐层递减**：① 命中率最高（独立设计 + 输入聚焦 + 结构化对照）→ ⑤ 命中率中等（依赖缺陷是否在实现里暴露）→ ⑦ 命中率最低（输入大 + 一次性 + 注意力分散）。**跳过 ① 不是「少一层防线」，而是「把最终保障交给命中率最低的环节」**——这是 §5.2 要求 ① 不可被下游补偿的结构性理由，**不是概率性判断**。
