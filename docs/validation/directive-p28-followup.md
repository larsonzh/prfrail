## 1 概要

**问题**：v1.50 的「运行时缓存目录例外」只写例外集成员可以保留，未禁止成员目录内新增空子目录；而 ② 只数 `tmp/` 下的递归文件、③ 只看 `tmp/` 的顶层名，两者都看不见例外集内部的空目录 ⇒ 例外条款留有缝隙。P28 另有两项遗留未收口（症状列只记 2 次同型偏离、处置列未覆盖「第 3 次后若特批继续」）；此外三条协作纪律（⑩ 停点回执 CI 取证 push 的推定授权、证据缺口表述、枚举优先于推导）没有正文落点。

**裁定**：第 4 项 = (a)——例外条款增「成员目录内不得含空子目录」句，并在 ⑩ 前终态回读新增第 ⑤ 条读数（断言：例外集内递归目录数 == 已知成员数），不做成 G 判据；第 5 项 = (d)——纪律 A 入 §11.2 正文，纪律 B 与 C 入附录 C.0al 的「附注」字段、仅留痕。

**结果**：准则升 v1.51（头部 / §0.3 / §5.1 / §9.3 / §11.2 / 附录 B.7.3 / 附录 C.0al 七处），两台账的 P29 块同步；三作用域 `TOTAL_FAIL=0`，自测 `SELFTEST: PASS 697/697`；未改代码、未改判据本体、未推 gitee。

**白名单 +1（`幻`）**：该条目不是「合法新词登记」，而是「转录契约逼出的逐字保留」——⑥ 报告 Section E 用了「文档幻觉」，转录契约（§11.3）禁止改写审查方原文，故 `幻` 必须保留并登记白名单。该字本身是合法中文词，不是生造词。今后若再遇到「转录带出新字」，仍按同一路径：不改写转录、登记白名单、报告写明理由；不得为了「白名单不膨胀」而改写审查方原文。

## 8 异常处理

### 8.1 临时件 D = 1：② 步骤 0 的误放件（自愈档）

② 的探针在步骤 0 把输出写到切片目录之外（`tmp/` 顶层），随即自删；`tmp/` 顶层零残留，产物未进入任何提交。按 `§9.3:886` 处置列「该目录之外的自身误放件按 §5.1 的自愈档处置」⇒ 本片临时件 D = 1。

### 8.2 过程偏离：② r2 的双层 BOM 与多处 `MM` 暂存

② r2 首次写盘叠了双层 BOM（`G4a` 报 `bom=2`），已剥为单 BOM 并重跑三腿；另有多处文件在改后未及时暂存，`G5(f)` 判红，逐个 `git add` 后转绿。两件均自报、自修、零残留，属常规自愈。

### 8.3 主控驳回 ③-L1（`§9.3:874`）的理由

③-L1 建议把「以 `git status --porcelain -uall` 等四条命令为准」改为五条。主控驳回：该句属 §9.3「SCM 陈旧显示」的诊断命令集，不是 §5.1 的 ⑩ 回读清单（回读中只有 ① 含 `git status`）；改之会暗示二者同一，且超出用户为第 1–3 项划定的落点（仅 `:886` 一行）。① 原设计亦判「保持不改」。

**D-2（⑧b 超指令改动，已由用户接受，不得作先例）**：⑧b 在「只改三处」指令之外，额外修正了 P29 台账「修法方向」行的时态（由「待 ① 两组裁定」改为「① 已裁定 = 第 4 项 (a) / 第 5 项 (d)」）。原因：`G6-1` 报时态不一致。四案枚举逐字保留、无增删行。性质 = 为门禁绿而多改一行；**不得作先例**。**今后做法**：遇 `G6-1` 红时**先停报备、等用户裁定**，不得自行改；本片属「⑧b 已写、门禁已红、停下代价大于改」的特殊情形，该前提不存在时必须先停。

**白名单实际 +3（`幻` / `膨` / `胀`）**：`幻` 由 ⑥ 转录带出；`膨` 与 `胀` 由登记 1 的逐字文本（「白名单不膨胀」）带出。三字均为合法中文词、非生造词，按「不改写逐字文本、登记白名单、报告写明理由」的既定路径处理。
