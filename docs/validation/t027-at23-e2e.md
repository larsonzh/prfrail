重跑字节确定性（⑤ 整改 F1）：`fillProjection` 原先把 `taskState` 与 `stepState` 写在 `for … range map` 的单一槽位上，Go 的随机遍历次序既让 verdict 字节不可复现，也会静默丢状态（实测 f5-pos 只留下 verify 步）。现改为按 key 排序后完整写出（`key=state; key=state`）。同形两腿（各自独立 run root）逐字段对比后，差异只落在真随时间变化的字段：`startedAt` 与 `endedAt`、`journal[*].at`、`mapping.elapsedMs`、进程身份（`journal[].detail.processId` 的 `pid`/`startToken`）、含采集时间戳的 manifest 与含 PID 的 `stub.pid`/`stub-child.pid` 摘要、绑定实测输入与时刻的 `requestRecordHash`（`notes[1]`）、以时钟生成事件 ID 的 `eventLogHash`，以及引用上述摘要的 `checks[].detail` 与 `candidateHash`；`verdictClass`、`chainState`、`taskState`、`stepState`、`observations`、`diff` 与全部断言的 `pass` 值逐字相同。

不可复现的反向**只能**记为“疑似反向”，不得记作“反向”。
