## 3. 新增条款要点（`docs/CONTRACTS.md` §7 / `docs/CONTRACTS_EN.md` §7）

1. **三态**：`proven` / `disproven` / `unresolved`（`observed`/`falsified` 只作证据注释，不作等级），与 A7 一致。
2. **判定单元 = （平台 × 前提 P）**：任何等级表述必须同时携带平台、前提与证据；禁止把某前提下的等级改述为无前提的平台级等级（平台级只可表述 `unproven` 默认态）；任何 `proven` 必须能追溯到平台 + 前提 + 证据。
3. **记 `proven` 的三项判据（同一前提下须同时具备）**：
   (a) 可复现注入或对照证据（有效轮落在允许集内、证据包可由轮次记录与 journal 复算、无真孤儿）；
   (b) **区分力门**（同一装置、同一写入器与同一记录级载荷下，负对照出现 ≥1 次丢失、正对照零丢失；**门不成立即封顶 `unresolved`**）；
   (c) **机制证据**（该轮所主张的持久化机制确实执行过）。
   **任一缺失即 `unresolved`**（且 `unresolved` 只表示未能建立主张，**不得读作"不耐久"或"已被证伪"**）；存在可归属反例（阶段命中且机制确已执行仍丢失）即 `disproven`。
4. **禁句式**：禁止"永久耐久 / 长期保证 / 已验证断电安全 / 跨前提普遍耐久"类表述；`proven` 只能表述为"该前提下、该装置与统计分辨率内未观测到反例，且机制确已执行，且装置具备区分力"。
5. **对象分离**：候选机制等级 ≠ **平台发布耐久等级**；平台等级只由该平台**生产实现所采用的机制**在覆盖目标部署环境的前提下的证据决定——排除"候选 `proven` ⇒ 平台 `proven`"的短路读法。
6. **运行期映射**：`unresolved` 与 `disproven` 一律按 `unproven` 行为执行（fail-closed 不变）。
7. **升级的解锁边界**：某（平台 × 前提）升为 `proven` 后，**仅在该平台、该前提覆盖的部署环境内**解除对应拒绝；**不解锁**任何其它前提或平台，**不豁免 AT-23**（仍必须通过）、**不豁免独立评审与协议先行**、也不放宽 `first-dispatch` 之外的任何门禁。平台等级升级必须协议先行修订本节、证据可追溯并通过独立评审。
8. **既有实例**：本地 Unix 文件系统上"新 link 创建成功且父目录 `fsync` 成功"在既有契约口径下视为满足全部判据的实例（其前提即"本地 Unix 文件系统类"）。
