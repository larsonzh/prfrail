- **F3 `partially`**：Agent 和 supervised 复核失败都返回 `failed`；撤销和证据根漂移有反例，但没有「摘要合形、策略未获独立批准，仍须零发布」的测试。

## F6 信任判定

**能。** `--authorization-ledger` 直接选择路径，加载器验证格式和内容摘要，不认证写入者。对原有 `run` CLI「调用者就是受信操作者」的模型，这不是实质变化，原入口也接收账本路径。但对能调用 `ai check`、却不应批准凭据接收端的主体，这就是自批路径。**F6 不闭合**；即使限定调用者可信，profile/凭据引用未匹配、已批准摘要未传到启动端这两点仍各自阻断。

## 须登记的可接受残余

- **F1**：后续产物失败不回滚已通过扫描并写入的对象；失败结果不引用先前产物。macOS 上实际声明产物仍可因无安全绑定能力而拒绝，不能把这个限制扩到无产物 hook。
- **F2**：正确时点的账本复核是快照，不是跨启动的事务锁；不承诺观察到快照之后才提交的变化。
- **F3**：不同 grant 的同 scope、不同 policy 可导致保守停发；这是可用性残余，不是批准绕过。历史 grant 被误认为当前批准不属于此项。
- **F4**：续租中断可留下陈旧本地 proof，导致拒发并需对账；不允许凭陈旧 proof 继续。**旧回执不可复核不是可接受残余。**
- **F7/F8**：`CredFree` 只证明释放，不宣称擦除 OS 内部副本；日志拒绝表仍可能把形似选项的合法值误拒。子进程自身未受控落盘是阻断，不是误拒残余。

## 最小整改与复审

1. **F1**：无产物直接返回空列表；有产物时从可信根在执行前绑定，之后沿用同一对象。补根替换和无产物反例。
2. **F2**：生产入口要求实时账本源，把内存替身限于测试；读完再取时钟。补无源、读期间过期和磁盘结算反例，均断言保留 R、零启动。
3. **F3**：从执行者不可写的来源核验明确获批的策略和候选证据根，拒绝旧 grant 与仅有风险确认的情况。把新证明要求限于相应发布路径，保留通用人工回执兼容性。
4. **F4**：发布事务持有真实进程级排他证明；换 PID 须证明前任已停。按 hash 保留每代租约原件并绑定 attempt。补双进程互斥和续租后旧回执复核。
5. **F5**：在 `Runner.Run` 核对真实 hook 定义摘要，分类字段只取冻结策略；声明矛盾即拒绝。补元数据冲突零执行反例。
6. **F6**：独立固定可信审批来源，核准完整接收端绑定；将同一批准摘要和文件身份传到启动，禁止重新选定。补自带账本、同地址换凭据引用、批准后换文件的零解析/零启动反例；保留非 BYOK 路径。
7. **F7**：预留终止符空间，消除或清零终端增长副本；让测试观察 builder 成功和失败时的 scratch、部分块和旧数组，分别验证删掉清零会变红。
8. **F8**：不能证明该子进程配置禁用未脱敏落盘时拒绝 BYOK；拒绝证据只用稳定分类，不散列参数值。补零启动和拒绝证据不随值变化的反例。
