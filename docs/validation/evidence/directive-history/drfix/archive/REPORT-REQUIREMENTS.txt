# DR-FIX 报告（⑧）与台账回写（⑧b）的强制内容清单

> 来源：用户 2026-09-22 裁决。⑧a/⑧b 必须逐条落实，**不得遗漏**；⑧ 完成后由 主控按本清单机械核对。

## R1 · 报告 §4 审查摘要：写入 ⑤ 的**独立贡献**（标明"⑤ 独立贡献，非 ① 输入"）

- 内容：**不对称性论证** —— 本包有两类**确定性**计数读（deny 路径 `accepted.Load() != 0`、DR-2 第二相 `connections.Load() != before`），它们在台账 5 次首跑红中**从未红过**；若真因是"共享 rig / 端口冲突 / 死锁"，这两类读点会**同等受害**。
- 用途：作为"**单一根因（200 与应用层 `Accept()` 之间无 happens-before 边）**"判定的**辅助证据**，并作为**证伪"共享 rig"假设**的独立佐证（§7.7 A12 角色）。
- **必须标注**：该论证由 **⑤ 预审独立提出**，**不是 ① 架构的输入**。

## R2 · 报告 §4：③ 的 F3 与 ① 的任务 A **连写**，注明"两条独立证据"

- 证据一（① 任务 A）：3 条 `AUDIT TRAIL BROKEN` 各自的路径含**各测试自己的** `t.TempDir()` 名（`…\TestTunnelWorksAcrossRealTLSThroughProxy…\001\proxy.jsonl` 等）⇒ 非共享临时目录。
- 证据二（③ F3）：两种形态（`write …` / `sync …`）在**全绿运行**中也逐字复现 ⇒ 属设计内 fail-closed 输出 / 次要噪声，与 flake 无因果关联。
- **两条独立证据指向同一结论**；写作时**连写**，不重复叙述。

## R3 · `-race` 覆盖缺口：**接受为已登记缺口（用户裁决 (a)）**，含两个条件

- **缺口的含义（必须写明）**：本包的并发语义（echo 计数 goroutine、logger 锁）在 **CI Ubuntu 腿没有 race 检测覆盖** ⇒ **Fix-3（`eventLogger.close()` 加锁）无法被 `-race` 独立验证**。
- **性质**：**不是代码缺陷**，是**覆盖缺口**，属**报告义务**。
- **登记位置**：报告 **§8 未执行事项** + **待议项**，明确写"**下次扩展 CI race 范围时本包入列**"。
- **(b) 不采纳**：`.github/workflows/**` 属 §1.6 的**不可绕过边界**，改它必须走独立 `[SLICE]`。
- **补充要求（验证深度诚实标注）**：报告"**已知边界**"节明写：
  > 本片对 Fix-3 的验证**只有单测幂等断言**（二次 `close()` 不 panic），**没有 race 检测**。

## R4 · DR 症状串规范化：确认，但**匹配依据必须双串**

- **DR 行同时记录两串**：
  - **历史串（修复前）**：DR-5 `target accept count = 0, want 1`；DR-2 `target must have been reached while the audit trail was healthy`
  - **规范串（修复后）**：`target accepts = %d, want %d`
- **匹配口径**：**修复前**的首跑红按**历史串**匹配；**修复后**按**规范串**匹配。
- 理由（写入报告）：只记新串会让未来拿**旧 run 日志**核对时对不上号。
- **DR-2 位断言强度 `≥1` → `==1`**：确认，且报告必须**显式写"这是加强，不是放宽"**（DR 处置口径含"不得放宽"，凡断言强度变化须标注方向）。

## R5 · ⑨ 的"3 连推"：本片验收①（用户明确支持）

- 判据：**3 连推全绿 ⇒ 修复验证成立**；**任一红 ⇒ 修复未生效，回 ①**（按 DR 处置口径边界③：修复后的复现 = "修复失败"证据，须单独登记）。
- 本片本质是**修复 flaky 测试**，一次 CI 绿**不能证明修复有效**；3 连推（每次观察 **Windows** 腿）是**最低可接受验证强度**。
- **这是本片 §12.1 A12 的独立佐证**（必须在报告中如此定位）。
- push 授权：**同轮授权覆盖 3 次 push**（每次推后观察 CI）。
