### 1.2 判定方法规约

1. **判定闭集** = {可达, 不可达, 未知}。`未知` 只允许用于人工门（G-G）；其余门必须由证据推出可达/不可达，证据不足时如实写「未知」并附核实方法，不得猜。
2. **每门四元组**：判据句 + 证据位置列表（全部 `file:line`）+ 判定 + 解锁句。
3. **解锁句模板**（固定）：「需要 X 具备 Y，当前证据 Z 显示…」——Z 必须是可定位的文件/行或证据包路径，禁止「需要进展」「待推进」类空话。
4. **DR-1 证据的引用口径**：DR-1 的 `available` 记录只支持一条推理——「同一 pin 上探针通道现已可驱动候选并产出最小真实响应」；**不支持**任何「候选兼容」「候选可启动」「装配完成」推理（依据 `docs/CONTRACTS.md:191` 的「配置合法、秘密存在、CLI/扩展已安装…均不足以证明 AI 可用」与本片边界）。

## 2. 五点确认的逐点方法

### 点 1：`--model` flag 与 `configuredAIProfile` 有无默认值 / fallback

- **结论出处**：`internal/console/ai.go:36-42`（`ai check` flag 集 = chain/channel/copilot/workspace/out/max-requests/json，**无 `--model`**）；`ai.go:229`（`configuredAIProfile`：按 channel 绑定→profileID→profile 三级查找，无默认值、无 fallback——任一缺即返回 `(零值, false)` ⇒ 上层报 `ErrAIChannelNotConfigured`）；`internal/adapters/ai_provider.go:51`（`Model == ""` 被拒）。**结论：无 `--model` flag；模型唯一来源 = 链配置 `ai.profiles[].model`；无默认值 / fallback。**
- **无需命令**（仓库文件即可证）。
- **证伪条件**：在 `ai.go` 或 `adapters` 中找到 `--model` flag 定义、内置 profile 常量、或 `configuredAIProfile` 的兜底赋值。

### 点 2：schema 里 `model` 字段是否 required

- **结论出处**：`schemas/` 目录 36 份 Schema 中**无任何一份覆盖链配置 `ai.profiles`**；目录中仅 `chain.schema.json:116/156/185` 出现 `model`，均属 task/codeStep 级**可选**字段（`required` 数组不含 `model`），与 `ai.profiles` 无关。⇒ 「schema 中 model 是否 required」**不适用**（无该 schema）。必填性由 Go 校验实现：`internal/adapters/ai_provider.go:51`（`Model == ""` 拒绝）+ `internal/console/config.go:387`（profiles/channels 非空）、`:394`（逐 profile `AIProviderProfileHash` ⇒ 同校验）。
- **需 ② 阶段复核项**：对 `schemas/*.json` 全文检索 `"profiles"` 与 `"ai"` 键做机械确认（我已按目录+grep 复核，但未逐文件读全）。
- **证伪条件**：找到一份被代码引用的、覆盖 `ai.profiles[].model` 的 JSON Schema（含 `required` 不含 model 的形态）。

### 点 3：`model: "auto"` 是否被 schema 或代码禁止

- **结论出处**：代码无任何 `"auto"` 比较（`internal/adapters/*.go` 检索 `"auto"` 仅 2 处测试命中）；`ai_provider.go:51` 只查非空/长度/空白；**测试把 `Model: "auto"` 当合法值**：`internal/adapters/ai_provider_test.go:13`（`TestAIProviderProfileHashAcceptsHostAndSecretAuthentication` 通过即证）、`ai_preflight_test.go:110`。schema 侧无覆盖。透传：`ai_probe_copilot.go:114`（`"--model", model` 原样传入）。**结论：不被禁止；作为普通值透传。**「auto」在 Copilot CLI 侧的实际语义属仓库外事实，**无探针额度 ⇒ 不可验证**，如实标注。
- **证伪条件**：找到对 `model` 与 `"auto"` 的等值比较、或 schema enum 排除 `"auto"`。

### 点 4：VS Code secretStorage / Copilot CLI 自有存储中的 BYOK 条目（只报存在性与条目标识名）

- **可只读枚举（② 阶段执行，主控记录）**：
  1. `cmdkey /list`——Windows 凭据管理器条目名（不读秘密）。**只读理由**：不写入、不联网、输出仅目标名。
  2. `Get-ChildItem Env: | Where-Object Name -match '^(COPILOT|DEEPSEEK|ANTHROPIC|OPENAI|AZURE)' | Select-Object -ExpandProperty Name`——只报环境变量**名**。只读理由：同上。
  3. 候选配置目录**文件名**枚举（如 `%USERPROFILE%\.copilot-cli`、`%APPDATA%\Copilot` 等）——只报文件名与存在性，**不读任何内容**。Copilot CLI 的确切存储布局属仓库外知识 ⇒ 「不确定，需 ② 阶段核实」，核实方法即上述枚举 + 与已记录事实交叉。
- **不可枚举（如实报告，不得猜测）**：
  - **VS Code SecretStorage**——扩展宿主加密存储，外部无可枚举 API；prfrail 是 Go CLI、不含 VS Code 扩展代码 ⇒ 该问题的这一半**只能写「不可枚举」**。
  - 任何文件/条目的**内容**（按「不读内容」约束与 §7.3 消毒纪律）。
- **仓库内唯一既有证据**：`docs/t027/REMAINING_SLICES.md:532`（DR-1 依赖行：2026-09-24 只读确认凭据管理器含 `https://github.com:larsonzh.copilot-cli`——这是 Copilot CLI 的 **host 认证条目，不是 BYOK API 密钥**）；`DEV_PLAN.md` B1 段（「未评估、未排除：BYOK `deepseek-anthropic` 与非 Copilot CLI 候选族」）。
- **证伪条件**：枚举结果中出现 BYOK 形态条目名（如 `ProofRail/deepseek`、`COPILOT_PROVIDER_API_KEY` 变量名、或候选目录下的密钥配置文件名）⇒ 报告按「存在性 + 条目标识名」记录，**仍不读内容**；出现任何可枚举 SecretStorage 的外部 API 也可推翻「不可枚举」。

### 点 5：prfrail 自有 secretStorage 机制与 OPERATIONS.md 的关系

- **结论出处**：`internal/adapters/ai_secret_windows.go:15`（前缀 `windows-credential:`）、`:57`（写入时 UserName 域 = `ProofRail`）、`:63-75`（`windowsCredentialTarget`：去掉前缀即 Credential Manager 目标名）、`Set/Resolve/Exists/Delete` 全部走 `CredWriteW/CredReadW/CredDeleteW`（generic 型、`Persist=LOCAL_MACHINE`）。**存储位置 = 当前用户 Windows Credential Manager（非文件）**；目标名格式 = 引用串去掉前缀（例：`windows-credential:ProofRail/deepseek` → 目标名 `ProofRail/deepseek`）。

- **证伪条件**：发现其它平台 backend（`ai_secret_*.go` 非 windows 实现）、或目标名转换规则不是「去前缀」。

## 5. 风险与停止条件

- **(a) 语义改动停止点**：五点中任一点若最终结论要求改动 CONTRACTS / schema / 授权契约语义 ⇒ **停止升级**、另立切片。本片初步核验五点均不指向（§2）；第 4 点若枚举到 BYOK 条目只是**事实**，不触发停止；触发停止的是「结论要求改契约」。
- **(b) OB-21 两分支**：
  - **仍不可达（预期）**：只刷新判定 + 登记（OB-51 行 + 可选 OB-21 更正注记），**不改代码**；影响 = B4/S1 exit 判读维持，DR-1 子项消除如实记入。
  - **可达（意外）**：只允许写进报告并**停下升级**——「可达」意味着 ①/② 某种解除，后续动作（是否启动 T027/B4）由用户裁决；本片**不得**据此改代码或推进 B4。
- **(c) 本片不能说的话**（违反即判据红/结论失真）：
  1. 不得写「部分通过」——`PARTIAL` 只属 §4.1 ⑦ 结论行枚举，报告与台账不得以此描述切片结论（T018 行本身也禁「部分通过」冒充）。
  2. 不得把 DR-1 的 `available` 读作「候选兼容」或「候选可启动」。
  3. 不得写「AT-23 机制腿通过 ⇒ AT-23 通过」。
  4. 不得写「OB-21 已闭环/已处置」——② 子项消除 ≠ 整条闭环，处置保持「待议」。
  5. 不得声称本机当前凭据条目状态未经枚举证实（第 4 点只报已枚举事实 + 不可枚举标注）。
  6. 不得把「T018 四门依赖候选进展」或「不依赖」说成单一结论——必须门级/任务级分开表述（§1 的 G-H 注）。
  7. 不得以 OB-37/ADR-014 为先例自行降级其他环节（仅 ⑦ 且已由用户裁定）。
  8. 不得声称「已运行命令」——所有执行发生在 ②-⑨ 环节并由主控记录，① 只读。
- **(d) 试点顺延第 4 次**：本片以 `[SLICE]` 起跑 ⇒ 依 §12.1 配套② 需升级用户裁决。用户切片定义本身即裁定（分级 `[SLICE]`），但留痕义务不变：报告 §4 记四要素 + 「不得作为先例」（DR-1 报告 §4 同款做法），§12.4 不另登记（顺延登记与试点台账口径同 DR-1）。
- **(e) 门禁红线**：G4b 新字（不得扩白名单 ⇒ 若报新字，换用已入语料同义词重写）；G6-4 禁行数/文件数；G2 禁占位串（收尾行用 DR-1 同款措辞）；G6-6 首状态词闭集；G1-b 版本一致；G6-2 成本 token（v1.15 行不写 ⑥×/⑦×）。
