## 2. 五面覆盖矩阵

**驱动形态总判**：五面**全部脚本化**（PowerShell 驱动脚本 + Go harness + 确定性负载），理由——① 五面的故障注入要求逐字节可复现的负载行为（`agent-stub` 的 `-mode/-no-marker/-torn-usage/-sleep/-exit-code` 标志由 `tools/agent-stub/main.go` 逐字确认存在）；② 真实 AI 候选按 F2 不可启动；③ 决策 2 微调要求「逐面写明理由 + 替代证据形式」——本方案对**每个无法用真实 AI 候选的面**都在表中给出理由与替代证据形式。**无任何面需人工操作**；决策 3 微调要求反向证据可复现——每次反向运行**同命令重跑 1 次**，两次 verdict 类一致才记「反向」，否则记「**疑似反向**」（报告字段 `reproducibility`）。

**判定口径（每面）**：正向 1 次 + 反向 1 次；正向 = 机制按契约行为；反向 = 注入故障被 fail-closed 捕获。判定依据逐项引用 CONTRACTS §7 冻结句（`docs/CONTRACTS.md` 第 205/217/221/225/227/229/231 行附近各段）。

| 面 | 场景（脚本化） | 正向：输入 / 命令 / cwd / 期望退出码 / 期望工件 / 判过 | 反向（注入故障）/ 期望可观察失败 / 可复现性 |
|---|---|---|---|
| **F1 隔离 workspace** | 装配 harness 经 `AgentRunnerPinnedCLILauncher` 在 `tmp/b4/runs/f1/…/workspace/` 启动负载 `-mode run -sleep 2s`；证据经 `PROOFRAIL_EVIDENCE_DIR` 重定向到 `<runRoot>/agent-runner-replay/runs/<requestId>/` | 输入摘要 = b4-chain.json + request-record.json 的 sha256；命令 = `.\bin\b4-e2e.exe -face f1 -case pos -run-root …`（由 `run-faces.ps1` 逐字记录）；cwd = `tmp/b4`；期望 harness 退出码 0 且 verdict=`completed`；工件 = `manifest.pre/post.json`、`diff.json`、`logs/stdout|stderr.log`（末尾 `proofrail-run-complete` 标记）、`events.jsonl`、`usage.json`（闭形状 `{calls,tokens,durationMs}`）、`managed-process.identity.json`；判过 = workspace 树除负载自写文件外无变化（pre/post manifest diff 精确等于负载自报集）+ 五枚事实摘要齐备且两两互异 | 负载 `-mode mutate-workspace` 在 workspace 写入 `agent-stub-mutation.txt` → postflight 重扫必须**不得**判 completed（或 diff 精确含该文件）；期望 = 事实门槛拒绝或 postflight 拒绝，**绝不**产生 task PASSED；可复现 = 同命令重跑，diff 逐字节相同 |
| **F2 timeout** | 负载 `-mode hang -sleep 30s`，`LaunchRequest.Timeout=5s`、`Grace=2s`；看门狗（`agent_runner_timeout.go`）判负后 `WaitAgentRunnerProcess` 上界内验证进程树消失 | 正向：verdict=`uncertain`（树已停 + 无 Facts）；退出码 0（harness 侧）但**终局非 completed**；工件 = 停机证据摘要 + 原因摘要入回执；判过 = 超时在 Timeout 附近触发（时间断言只证区间，同 A6「±50ms 下界」口径）+ 回执含 `stop` 证据 + 无 Facts | 反向 = 负载 `-mode spawn -child-life 1h -sleep 5s`（派生长命子进程）超时后停机必须把**整棵进程树**带走；期望 = `child` PID 在验证窗口内消失（`processGroupAlive` 路径）；若任一轮树残留 → 记「疑似反向」并升级 ⑤；可复现 = 重跑两次残留进程集合均空 |
| **F3 日志缺失** | 负载 `-mode run -no-marker`（`tools/agent-stub/main.go` 的 `noMarker` 标志：写日志但省略完整性标记） | 正向：verdict=`uncertain`（`LogHash` 门槛缺口）；判过 = 回执原因摘要可解析、**非** completed、Facts=nil | 反向 = 完整 `run` 模式（标记在）判 `completed`——证明缺口判别力是**真判别**而非全拒（对照口径同 B3a 双向标定）；再以 `-torn-usage`（撕裂 usage）复证缺口门槛；期望 = 前者 completed / 后者 uncertain；可复现 = 两个方向的 verdict 类各重跑一致 |
| **F4 未知恢复** | 负载 `-mode crash -exit-code 7 -sleep 3s` 或外部 `StopAgentRunnerProcess` 在固定延时后停机；随后**重启 harness 进程**（新进程、同一 run root）走 `Recover` | 正向：重开后 step 处于 `TERMINAL_PENDING`/`RUNNING` 不确定清单（`internal/chain/recover.go:23-25` 含 `TERMINAL_PENDING`），chain `PAUSED`（`recovery-uncertain`），**零 relaunch**（launches 回执已存在 → `unknown-block`）；判过 = 进程清单无第二实例 + chain 不离开 PAUSED + 无新 launch-intent | 反向 = 伪造 `priorCompletionHash` 不匹配的 resume 终局 → `SubmitAgentRunnerTerminal` 以 `ErrAgentRunnerResumeContinuityUnproven` 零写拒绝；期望 = 事件日志字节不变（拒绝前后 hash 相等）；可复现 = 两次注入均拒绝且日志摘要相同 |
| **F5 exit 0 后重扫 + 独立 gates/review** | 完整闭环：负载 `-mode run` 干净退出 0 → completed 终局 → `TERMINAL_PENDING→PASSED` → **真实 postflight 端口**（harness 实现，重捕 manifest + 与父快照算 diff + 范围/秘密/类型/副作用扫描，复用 `internal/snapshot` + `internal/gates`）→ `REVIEW_PENDING` → acceptance/freeze → gate hook（真实命令作用于 workspace）→ review 端口 → promotion → task PASSED | 正向：verdict=`completed` 且 chain 走完全部下游（`REVIEW_PENDING`→…→`PASSED`）；判过 = 事件日志可见 `postflight` 判定事件 + gate/review/promotion 各转移 + **exit 0 本身不产生 PASSED**（PASSED 唯一写点在 `runTask` 尾部）；同时按 A5 报告 §残余边界记录**「engine gates 排在 `Acceptance.Accept` 之前 vs CONTRACTS §7『freeze 后跑 gates』」的对账结论**（见 §5 风险 R5） | 反向 = 完成并结算后篡改 workspace（写已知字节文件）再重放 postflight → 必须 `postflight-rejected` → task `REPAIR_PENDING` + chain `PAUSED`（`STEPS_RUNNING→REPAIR_PENDING` 仅 postflight 拒绝使用）；期望 = 绝不 REVIEW_PENDING/PASSED；可复现 = 同篡改字节重跑，verdict 类一致 |

**每面用例统计口径**：5 面 ×（正 1 + 反 1）= 10 次核心运行；F1/F2/F3/F4 反向各附带 1 次对照重跑（可复现性证明）与 F4 反向 1 次拒绝前后 hash 对照——**报告只记实际执行数**（G6-4 见 §7，不得预写总数）。
