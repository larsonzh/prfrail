## 三、High 级发现

### H1｜§4.1 闭集枚举与附录 B.6 模板直接冲突（H2 只修了一半）

**位置**：§4.1:305（"**裸 `PASS` / `FINDINGS`（无前缀）或表外形态视为格式偏离**"）；§4.1:314（⑦ 的前缀 = `FINAL REVIEW` / `RE-REVIEW` / `BLIND REVIEW`）；B.6:906（"输出末尾必须有一行：`` `PASS` / `FINDINGS` / `RE-REVIEW: PASS` / `INDEPENDENT SCAN: PASS` 等规定枚举``"）。

**冲突逐条**：
1. B.6 教的 **`PASS` / `FINDINGS` 是裸 token** ⇒ 按 B.6 派单产出的报告，会被 §4.1 判为**格式偏离**（按 §7.2 处置 = 重发一次，计入 ⑥ 的 3 次上限）；
2. B.6 **完全没有** `FINAL REVIEW` / `BLIND REVIEW` 前缀 ⇒ **⑦ 独立终审在模板里至今没有合法结论行**（这正是 v1.0 H2 的原文，四个版本后在 §4.1 修了、在 B.6 没修）；
3. B.6 仍保留开放式"**等规定枚举**" ⇒ 与 §4.1「闭集」直接矛盾。

**为何是 High**：主控派 ⑦ 时按 B.6 模板写输出要求，审查方照做 ⇒ 结论行不合规 ⇒ 整轮作废或需重发（⑦ 的额度是 1+1，重发即触顶）。属"照章执行却静默走错"。

**建议修法**：把 B.6:906 改为引用 §4.1 闭集表：`输出末尾必须有一行，形态取自 §4.1 闭集枚举表（⑦ 终审 = `FINAL REVIEW: …`；复审 = `RE-REVIEW: …`；盲审 = `BLIND REVIEW: …`；⑥ = `INDEPENDENT SCAN: …`）；不得使用裸 `PASS`/`FINDINGS`。`

### H2｜§1.6 引用不存在的「§8.2 的 `[ROUTINE]` 行」

**位置**：§1.6:154（"另：`[ROUTINE]` 档的档位口径见 **§8.2 的 `[ROUTINE]` 行**"）；§8.2:581–587（表仅 5 行：简单 / 中等 / 复杂 / 高风险 / ⑦ Codex）。

**为何是 High**：`[ROUTINE]` **可产生仓库改动**（§1.6:104、:122），却是三档中**唯一没有档位规定**的一档；且 §1.6 给了一个**指向不存在行的引用** ⇒ 主控按引用去查必然落空，只能临场解释。这是 R3 的 A8（Medium）未被处置、且在本次修订中**升级为悬空引用**的结果。

**建议修法**：§8.2 表增一行 `日常 [ROUTINE] | 沿用当前会话档位（不按本表设定）| — | — | —`；或删掉 §1.6:154 的引用句并改为在 §1.6 内直接写明口径（**只写一处**）。

### H3｜model 调用串半修：§2.2 已改，附录 B 七处模板未改

**位置**：§2.2:194–204（`modelId` 列 + "`modelId` 是调用串的唯一权威…**UI 显示名…不得写入任务包或附录 B 模板**"）vs 附录 B:822 / :839 / :853 / :867 / :882 / :897 / :898（**全部仍写 `model='DeepSeek V4 Pro (deepseek)'` 等 UI 显示名**）。
