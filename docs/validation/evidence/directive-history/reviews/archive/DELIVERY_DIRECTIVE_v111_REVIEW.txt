## 三、High 级发现

### H1｜`model` 调用串三处口径不一致（跨 11 个版本未修）

**位置**：§2.2:93–99 表列（写作 `DeepSeek V4 Pro (deepseek)` / `MAI-Code-1.1-Flash (copilot)` / `GPT-5.3-Codex (copilot)`）；R2.2:192（"只写现役模型 ID。Flash 只写 `deepseek-flash`"）；附录 B 模板 `:784 / :801 / :815 / :829 / :844 / :859 / :860`（写作 `model='DeepSeek V4.1 Flash (deepseek)'` 等）。另 §2.4:210 用小写 ID `mai-code-1.1-flash`。

**判据**：R2.1:191 声明"不传 `model` 会静默回落到会话主模型"；§2.3 声明"子代理自报模型不可信"。⇒ model 串取错后**没有任何事后校验能发现**。

**为何仍是 High**：表与模板给的是**含空格与括号的 UI 显示名**，与 ID 串不是同一取值；按表照抄违反 R2.2，按 R2.2 照抄使表与全部模板失真。v1.7 修的是"角色文件里的 `model` 键"（G5-a/G5-b），**与"调用时传什么串"是两个不同对象**，本条从未被触及。

**建议修法**：§2.2 增列 `modelId（调用串，唯一权威）` 与 `UI 显示名（仅供人工核对）` 两列，全表统一为 ID；R2.2 补"UI 显示名不得作为调用串写入任务包或模板"；附录 B 七个模板的 `model='...'` 改为 `modelId` 取值；可选加机械判据 G8：**附录 B 中 `model=` 取值集合 ⊆ §2.2 `modelId` 列**。

### H2｜结论行枚举仍未固定（跨 11 个版本未修）

**位置**：§4.1:283（`如 PRE-REVIEW: PASS / FINDINGS / `**`RE_`**` / INDEPENDENT SCAN: ...`）；B.6:868（`` `PASS` / `FINDINGS` / `RE-REVIEW: PASS` / `INDEPENDENT SCAN: PASS` **等规定枚举** ``）。

**为何仍是 High**：
1. `RE_` 是**残缺 token**，属 G2 定义的占位符残留——它在 §4.1 里已存活 11 个版本；
2. B.6 允许**裸** `PASS` / `FINDINGS`（无前缀），而 ⑥ 与 ⑦ 共用同一载体 `independent-reviewer` ⇒ 主控**无法机械判定一份报告出自 ⑥ 还是 ⑦、是终审还是扫描**；
3. ⑦ 独立终审**至今没有专属结论行前缀**（`RE-REVIEW: PASS` 只覆盖复审轮）；
4. "等规定枚举"是开放式表述 ⇒ 不可核验。

**实测自证**：本报告按 §4.1 也**无法**输出一条合规结论行——准则未定义"准则文档评审"角色。这正是 H2 的实证。

**建议修法**：在 §4.1 建**闭集枚举表**（①–⑧ 逐角色给前缀 + 枚举值），附录 B 引用之；加规则"结论行必须由『前缀 + 枚举值』组成，裸 `PASS`/`FINDINGS` 视为格式偏离，按 §7.2 格式偏离处置"；删除 `RE_`。

### H3｜协议先行仍无合法执行人（跨 11 个版本未修）

**位置**：§1.4:84（"CONTRACTS 双语 → schema / fixtures → 代码"）；§4.2:295（实现者**禁止**"改非代码文档"）；B.2:804（要求实现者"遵守协议先行（先改 CONTRACTS/schema/fixtures）"）；§3.2:248（主控**不原创** CONTRACTS/schema/fixtures）。

**为何仍是 High**：CONTRACTS 是 `.md`、schema/fixtures 是 `.json`，按 §4.2 字面属"非代码文档"⇒ 实现者被禁改；按 B.2 又被要求先改。主控禁原创，架构师/审查层只读，文档工程师在 §5.1 的 ⑧a（⑦ 之后）才登场。**协议先行这一步在当前角色集里没有合法执行人**，且 §5.1 流水线不存在独立的"改 CONTRACTS"环节。这是"规则自相矛盾 ⇒ 执行者只能临场解释"的静默失败源。

**建议修法**：① 明确"CONTRACTS/schema/fixtures 属**契约工件**，修改权归实现者（②），不计入 §4.2 的'非代码文档'禁止项"；② §4.2 实现者禁止列改为"禁止改除 CONTRACTS/schema/fixtures 之外的非代码文档"；③ §5.1 在 ② 内标注子步 `②a 契约 → ②b 代码`，使 R5.2「每环有产物」可核验。

### H4｜试点闭环断裂：§12.2 触发后未执行、未记录豁免，且 §12.1 指标不可复算

**位置**：§12.1:651–657（基线表）；§12.2:661（回退条款）；OB-14:684（`DR-FIX` 试点自捕获率 **2/5**，目标 **≥ 3/4**）。

**(a) §12.2 的强制动作无一执行，且无豁免记录**：§12.2 白纸黑字规定"试点**未达标**的回退路径：① 暂停本准则；② T027 相关切片恢复按 v3.1 执行；③ 其余仓库活动暂停，等待用户裁决"。OB-14 明确记载 DR-FIX 试点**未达标**。而实际轨迹是：v1.10（`GATES-EXT`）与 v1.11（`DIRECTIVE-V1.11`）继续在本准则下执行，三项动作一项未做，**也没有任何 ADR、观察项或用户裁决记录这次"不回退"**。⇒ 一条强制条款在触发后既未执行、也未书面豁免。这与 §0.2"本准则自身也是被验证对象"直接冲突。

**(b) 指标分母漂移，结论不可复算**：§12.1 定义"缺陷自捕获率 = 我方发现 ÷ 总发现"，基线却写作 **1/4**（原文口径是"4 类遗漏中 3 类由用户/审查方发现"⇒ 分母是**遗漏类**），目标 **≥ 3/4**，而 OB-14 实得 **2/5**（分母变成**总发现条数**）。同一指标在两个分母之间漂移，"总发现"的计数规则（条 / 类 / 去重口径）**从未定义** ⇒ 2/5 与 3/4 严格来说不可比，§12.2 的回退决策挂在一个不可复算的数上。

**建议修法**（择一并写入文本，勿留待下次）：
1. 在 §12.1 固定分母定义：`总发现 = 我方发现 + 审查方发现 + 用户发现`（按**条**计，同一根因合并为 1 条，去重规则写明），并规定"任一指标未达标即判试点未达标"；
2. 为 DR-FIX 试点**补一条裁决记录**（ADR 或 §12.4 观察项），明写"试点未达标但经用户裁决继续，理由 X，复评时点 Y"——把既成事实变成可审计的裁决，而不是沉默；
3. 若确实要沿用"扩展后复评"的路径（OB-14 的建议），则须在 §12.2 增一款"**复评条款**"，否则 §12.2 与现状的裂口会持续扩大。

### H5｜§5.3 的 ⑧c「重跑至全绿」判据当前不可满足

**位置**：§5.1:337（⑧c 含"编码门禁（§6.1 编码行 / §6.3 G4，**全类型逐文件核验，不只变更集**）"）；§5.3:367（"⑧c 收尾清洁发现问题 ⇒ 就地修复并**重跑 ⑧c** 至全绿"）；OB-27:705。

**为何是 High**：OB-27 已实测——全仓逐文件核验会报 3 个**既有**违规（`b2-2026-09-17/measuring/probe10-dir-listing.raw.txt` 为 CRLF；`b3b-2026-09-21/{session,variant}/pin.json` 带 BOM），这 3 个文件**不违反 G4a**（其作用域明写"变更集"），违反的是 ⑧c 新增的"不只变更集"口径。本片的处置是"**临时豁免**"，但：
1. 该豁免**只写在 OB-27 里**，未写入 §5.1/§5.3 正文 ⇒ 下次执行 ⑧c 的人读到的是"重跑至全绿"，撞上同一堵墙；
2. 豁免与 **B2 保真裁决 / `.gitattributes` 的 `*.raw.txt -text`** 直接冲突（OB-27 自己点明），三方口径未裁决；
3. 结果与 §6.3 的既有教训同类——OB-3（G4b）、OB-5（G3）都是"判据不可满足"被判为必须修的缺陷，**⑧c 是同一类缺陷的第三次出现，且这次带进了强制环节**。

**建议修法**：把冻结证据包豁免**写进 §5.1 的 ⑧c 条目**（严格限定"已归档、带 MANIFEST/SHA256SUMS 的冻结证据包"），并明写"⑧c 对证据包改做**自洽性核验**（MANIFEST/SHA256SUMS 可校验）而非编码改写"；同时裁决 `*.raw.txt` 的 `-text` 与 ⑧c 的优先级。
