### 1.2 实测证据（逐条可复核）

1. **Flash 模型标识**：`"DeepSeek V4.1 Flash (deepseek)"` **被 `runSubagent` 接受**且子代理确实运行。扩展 `out/consts.js` 的模型表：`id: 'deepseek-flash'`、`name: 'DeepSeek V4.1 Flash'`、`family: 'deepseek'`、思考档 `supportedEfforts: ['low','high','max']`、`defaultEffort: 'high'`。
2. **旧 ID 已退役**：`deepseek-v4-flash` 与 `deepseek-v4-flash-vision-exp` 被列入 `out/provider/retirement.js` 的 `LEGACY_FLASH_MODEL_IDS` ⇒ 新准则**只许写** `deepseek-flash`。`deepseek-v4-pro`（`name: 'DeepSeek V4 Pro'`）仍为现役。
3. **Flash 子代理可执行命令**：探针（`quick-verifier` + 显式 Flash）成功运行 `node --version`（v24.17.0）、`go version`（go1.27.0 windows/amd64）、`git status --porcelain`（EMPTY）。
4. **Flash 子代理默认无写文件能力**：同探针自报 `CAN_EDIT: no`，工具清单中无任何写入/编辑工具。
5. **"edit 载体 + Flash 模型" 组合可用（关键）**：`standard-builder`（agent 文件声明 `tools: ['read','search','edit','execute']`）+ 显式 `model: DeepSeek V4.1 Flash (deepseek)` ⇒ 成功创建 `tmp/probe-flash-edit.txt`（`LEN=13`，hex `50 52 4F 42 45 2D 4F 4B 2D 37 66 33 61`，**无 BOM、无尾部换行**）、`Get-Content` 读回一致、`Remove-Item` 删除后 `Test-Path=False`、`tmp/` 无残留。⇒ **实现者/测试/文档层的载体今天就存在**。
6. **`runSubagent` 是串行阻塞的**：工具契约明确 "Agents do not run async or in the background, you will wait for the agent's result"。⇒ 参考稿 v1.0 §4「② 并行调度实现者和测试工程师（可并行）」**不可实现**，必须改写为串行（或改由一名子代理同时产出实现+测试）。
7. **子代理自报身份不可靠**：同一次 Flash 调用自报 `GitHub Copilot（系统提示声明为 DeepSeek V4.1 Flash）| vendor=unknown`；另一次自报 `effort=unknown`。⇒ 档位/身份**不得以子代理自报为凭**，只能由 operator 在 UI 侧设定并记录（与 v3.1 §3.7「模型无法感知/确认/自改档位」一致）。
8. **主控与实现者同模型的档位冲突**：二者同为 `deepseek-flash` ⇒ **思考档位无法分离**（把 Flash 调到 low 会同时降低主控档位）。参考稿 v1.0「实现者 Low / 主控 High」在当前模型配置下**不可同时满足**。
9. **成本梯度（扩展 `out/consts.js` 定价，USD / 百万 token，offPeak 的 cacheMissInput / output）**：Flash `0.15 / 0.6`；V4 Pro `0.66 / 1.98`（≈4.4× / 3.3×）。⇒ 把**编码、测试、文档、门禁执行**下沉给 Flash 子代理是**单价最省**的杠杆；Codex/MAI 仍是最贵的两个环节，须保留既有调用上限。
10. **角色定义不可版本化**：`.github/agents/` 在 `.gitignore` 内（`git check-ignore` 命中），且 agent 文件头声称由 `_config.yaml` 生成——**该文件在仓库内不存在**。⇒ 角色集是**本机私有、不可复现**的。

### 1.3 由此得出的三条架构硬约束（须写入新准则）

- **C1 审查方（①③③.5④ 中除主控外的全部）都没有 `execute`** ⇒ 「主控把**原始证据落盘**并把**路径**交给审查方」必须成为硬规则（本会话 `tmp/b3c-review.diff` 已验证有效；否则 ④ 复审会再空转一轮）。
- **C2 只有"edit 载体 + 显式 Flash 模型"能写文件** ⇒ 实现/测试/文档三类角色**必须**走该组合；只传模型不选载体、或选 `quick-verifier`，都拿不到写入能力。
- **C3 子代理调用串行且不在后台** ⇒ 流程表必须是串行流水线，"并行"只可出现在主控自身的**工具调用层**（例如同一条消息里发多个只读命令），不可出现在子代理层。
