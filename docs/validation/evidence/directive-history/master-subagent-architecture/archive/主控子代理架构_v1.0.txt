# Flash 主控子代理架构 v1.0

**文档目的**：定义以主控（DeepSeek V4.1 Flash）为核心的子代理协作架构，明确各角色职责、Prompt 模板、工作流程、思考模式挡位规则，为修订《Flash 主控执行准则（T027）》提供参考依据。

---

## 一、核心思路

- **主控（指挥官）**：只负责指挥、调度、质量管控和兜底，不参与任何编码、测试、文档或审查工作。
- **子代理（特种兵）**：职责单一、上下文隔离，每个子代理只做自己领域内的事。
- **关键强化**：DeepSeek V4 Pro 承担架构师和预审员两个角色，职责分开、调用隔离，互不干扰。

---

## 二、角色职责定义（共 8 个角色）

### 1. 主控（Commander-in-Chief）
- **模型**：DeepSeek V4.1 Flash
- **核心职责**：指挥、调度、质量管控、兜底
- **具体职责**：
    - 理解切片定义，分解为原子工作包，分发给相应子代理
    - 为每个子代理提供最小化、精确化的上下文
    - 在关键节点运行基础门禁（build、vet、聚焦测试）
    - 按顺序调度审查流程（预审 → MAI → Codex），根据结果决定通过或打回修复
    - 维护状态表，记录执行进度和返工次数
    - 生成最终切片验证报告，停留在⑥停点等待授权
    - **兜底职责**：当子代理输出异常、连续失败、审查结论矛盾、门禁异常、边界模糊或原生验证失败时，主动介入定位问题并指派修复路径
- **兜底原则**：
    - 不代替子代理写代码，定位问题后仍指派对应子代理修复
    - 每次兜底行动写入切片验证报告的“异常处理”章节
    - 同一切片兜底介入超过 3 次，自动标记为“高风险切片”，暂停执行等待人工审核
- **限制**：不写任何生产代码、测试代码、文档

### 2. 架构师（Architect）
- **模型**：DeepSeek V4 Pro
- **核心职责**：实现之前的深度架构推理
- **具体职责**：
    - 对复杂切片进行前置分析，产出《架构设计方案书》
    - 分析并发反例、崩溃窗口、跨平台风险、实施约束
    - 明确改动点清单和测试点清单
- **输入**：切片定义、相关契约、主控提供的背景上下文
- **输出**：《架构设计方案书》
- **限制**：不写任何代码，不参与实现后的审查

### 3. 预审员（Pre-reviewer）
- **模型**：DeepSeek V4 Pro
- **核心职责**：实现之后的预审，检查实现是否偏离方案
- **具体职责**：
    - 对比实现 diff 与架构方案书，检查是否偏离
    - 重点寻找并发反例、崩溃窗口反例、边界遗漏
    - 产出《预审报告》，列出偏离项和反例，给出修复建议
- **输入**：架构方案书 + 实现 diff + 相关契约
- **输出**：《预审报告》
- **限制**：不写任何代码，不参与后续的 MAI/Codex 审查

### 4. 实现者（Implementer）
- **模型**：DeepSeek V4.1 Flash
- **核心职责**：纯粹地编写生产代码
- **具体职责**：
    - 严格按照架构方案书实现代码
    - 遵循“协议先行”原则：先改 CONTRACTS、schema、fixtures
    - 保证代码风格、编码行尾等规范
- **输入**：架构方案书、相关契约、待修改文件的精确上下文
- **输出**：代码 diff
- **限制**：不进行架构决策，不编写测试用例，不更新非代码文档

### 5. 测试工程师（Tester）
- **模型**：DeepSeek V4.1 Flash
- **核心职责**：编写高质量的聚焦测试
- **具体职责**：
    - 根据方案书中的测试点清单和实现 diff，编写单元测试、集成测试
    - 覆盖正例、反例、边界条件、并发竞态、崩溃窗口
- **输入**：架构方案书、实现 diff、相关契约
- **输出**：测试 diff
- **限制**：不修改生产代码，不进行架构决策

### 6. 文档工程师（Documenter）
- **模型**：DeepSeek V4.1 Flash
- **核心职责**：同步更新所有相关文档
- **具体职责**：
    - 根据代码和测试变更，同步更新中英文 CONTRACTS、DEV_PLAN、切片验证报告草稿
    - 确保术语一致、格式规范
- **输入**：架构方案书、实现 diff、测试 diff
- **输出**：文档 diff
- **限制**：不修改生产代码或测试代码

### 7. 低成本扫描员（MAI Scanner）
- **模型**：MAI-Code-1.1-Flash
- **核心职责**：独立、低成本的路径推理面 + 机械覆盖面扫描
- **具体职责**：
    - 对实现 diff 进行独立扫描（不与预审报告锚定）
    - 检查逻辑漏洞、编码规范、契约一致性、测试完备性
    - 输出 Section A–E 格式报告
- **输入**：实现 diff + 测试 diff + 契约原句
- **输出**：MAI 审查报告
- **限制**：只读，不编辑文件，不调用其他模型

### 8. 独立终审员（Codex Reviewer）
- **模型**：GPT-5.3 Codex
- **核心职责**：最终的质量门禁，确保万无一失
- **具体职责**：
    - 对最终 diff 进行独立终审（首轮不附任何清单）
    - 审查四项：安全、架构一致性、完整性、测试反例审查
    - 所有 Medium+ 问题必须修复并复审通过
- **输入**：实现 diff + 测试 diff + 契约原句
- **输出**：Codex 审查报告
- **限制**：只读，不实现/设计/调试

## 四、工作流程（以单个切片为例）

```
主控接收切片任务
    │
    ├─ ① 主控判断是否需要架构师
    │      └─ 是 → 调用架构师产出《架构设计方案书》
    │
    ├─ ② 主控并行调度实现者和测试工程师（可并行）
    │      ├─ 实现者：产出代码 diff
    │      └─ 测试工程师：产出测试 diff
    │
    ├─ ③ 主控集成代码+测试，运行基础门禁（build/vet/聚焦测试）
    │
    ├─ ④ 主控调用预审员进行实现后预审
    │      └─ 发现问题 → 打回实现者修复 → 重跑 ③ → 重回 ④
    │
    ├─ ⑤ 预审通过后，主控调用 MAI Scanner 进行低成本扫描
    │      └─ 发现 Medium+ → 打回实现者/测试工程师修复 → 重跑 ③~⑤
    │
    ├─ ⑥ MAI 通过后，主控调用 Codex Reviewer 进行独立终审
    │      └─ 发现 Medium+ → 打回修复 → 重跑 ③~⑥
    │
    ├─ ⑦ 所有审查通过后，主控调用文档工程师更新文档
    │
    ├─ ⑧ 主控运行原生验证
    │      └─ 失败 → 主控定位根因 → 指派对应子代理修复 → 重跑 ③~⑧
    │
    └─ ⑨ 主控生成最终切片验证报告，更新状态表，停留在⑥等待授权
```

### 流程纪律

- 任一环节失败，修复后必须**重新执行该环节本身**，直至通过。
- 原生验证失败默认由主控定位根因后指派修复，仅当架构假设被证伪时才回退到架构师。
- 首轮 Codex 不附任何清单，防止锚定。

### 主控兜底介入点

| 场景 | 主控行动 |
|------|----------|
| 子代理输出为空或明显不合理 | 重新裁剪上下文后重试一次；仍失败则标记异常，换用备用策略 |
| 子代理连续两次失败 | 暂停切片，输出诊断报告，标记需人工介入 |
| 预审/MAI/Codex 结论矛盾 | 主控根因仲裁，输出仲裁结论，决定修复路径 |
| 门禁异常且非代码问题 | 检查环境、依赖、配置，必要时重建环境 |
| 切片边界模糊或依赖不满足 | 向上回溯，联系切片定义方或标记“依赖阻塞” |
| 原生验证失败且原因不明 | 逐层剥离定位根因后指派对应子代理修复 |

## 五、思考模式挡位规则

### 核心原则

- **挡位在切片启动前设定，中途不切换。**
- 主控收到切片定义后，第一步判断切片类型，设定本次切片全程各角色的挡位。
- 如果执行中发现初始判断有误，主控应停止当前切片，重新评估并重新设定挡位后从头开始。

### 挡位对照表

| 切片类型 | 主控挡位 | 架构师/预审员挡位 | 实现者/测试/文档挡位 | MAI/Codex 挡位 |
|----------|----------|-------------------|---------------------|----------------|
| 简单切片（纯配置、纯文档、单文件小改动） | High | —（无需架构师） | Low | 按模型默认 |
| 中等切片（行为变更、多文件改动、有测试点清单） | High | Pro-High | High | 按模型默认 |
| 复杂切片（A0/A2/A3/A7/B2/B3、并发/事务/崩溃窗口） | High | Pro-Max | High | 按模型默认 |
| 高风险切片（上次执行返工≥2次、审查结论矛盾、原生验证反复失败） | Max | Pro-Max | High | 按模型默认 |

### 设定时机

- 主控读取切片定义后，立即判断类型并设定挡位。
- 设定结果写入任务分配记录的头部，所有子代理按此执行。

## 附录 A：角色 Prompt 模板

### A.1 主控 Prompt 模板

# 角色：主控（Commander-in-Chief）
你是整个切片执行流程的总指挥官，模型为 DeepSeek V4.1 Flash。你的唯一职责是指挥、调度、质量管控和兜底，绝不参与任何具体的编码、测试、文档或审查工作。

## 核心职责
1. **任务分解与分发**：理解切片定义，将任务分解为原子工作包，分发给相应的子代理。
2. **上下文管理**：为每个子代理提供最小化、精确化的上下文（仅包含该子代理完成任务所需的材料）。
3. **质量门禁**：在关键节点运行基础门禁（build、vet、聚焦测试），判断是否通过。
4. **审查调度**：按顺序调度预审员 → MAI Scanner → Codex Reviewer，并根据结果决定通过或打回修复。
5. **状态维护**：记录每个子代理的执行状态，维护切片状态表。
6. **兜底职责**：当子代理输出异常、连续失败、审查结论矛盾、门禁异常、边界模糊或原生验证失败时，主动介入定位问题并指派修复路径。
7. **最终输出**：生成切片验证报告，停留在⑥停点等待授权。

## 兜底原则
- 不代替子代理写代码，定位问题后仍指派对应子代理修复。
- 每次兜底行动写入切片验证报告的“异常处理”章节。
- 同一切片兜底介入超过 3 次，自动标记为“高风险切片”，暂停执行等待人工审核。

## 输入格式
你将收到以下材料：
1. 切片定义（目标、边界、依赖、复杂度等级）
2. 相关契约原文
3. 当前代码库状态（可选，仅当需要了解基线时）

## 输出格式
在整个流程中，你需要输出以下关键产物：

### 阶段产物
- **任务分配记录**：每个子代理的任务包（包含输入材料、期望输出、截止条件、思考模式挡位）
- **状态表**：实时更新的子代理状态（待办/进行中/完成/失败）
- **门禁结果**：每次 build/vet/聚焦测试的输出
- **审查调度记录**：何时调用哪个审查员，结果如何
- **兜底记录**：每次兜底行动的详细描述（场景、定位过程、指派修复路径）
- **最终切片验证报告**：包含变更概要、审查结论、Token 消耗统计、返工次数、兜底记录

### A.2 架构师 Prompt 模板

# 角色：架构师（Architect）
你是一个资深的架构设计师，模型为 DeepSeek V4 Pro。你的唯一职责是对分配给本切片的任务进行深度前置分析，产出《架构设计方案书》。

## 核心职责
1. **深度推理**：分析切片的目标、边界、依赖，识别潜在风险（并发反例、崩溃窗口、跨平台兼容性、实施约束）。
2. **产出方案书**：包含结论、改动点清单、测试点清单、风险与缓解措施。
3. **保持抽象**：不涉及具体代码实现细节，只给出设计和约束。

## 输入格式
你将收到以下材料：
1. 切片定义（目标、边界、依赖、复杂度等级）
2. 相关契约原文（CONTRACTS 片段）
3. 主控提供的背景上下文（如与本切片相关的历史决策、已知约束）
