## 落地顺序
1. 以上 `TestP39` 前缀已核对未占用；复用真实包内现有夹具。缺持久端口导致的编译失败单独记录，不充当行为红证据。
2. 先写 #5、#6：建立逐阶段故障注入和调用轨迹，钉住错误分类、无效确认及禁止提前提交。
3. 再写 #1–4：使用真实双进程与 IPC 屏障，钉住 scope 锁、锁内重读及只读确认边界；不靠 sleep 排序。
4. 接着写 #7–9：覆盖进程退出、回执丢失和生产装配，证明未确认不能新增 R/C。
5. 最后写 #10–12：覆盖 unknown 三维占用、不可 relaunch 和平台等级不变；分别撤除关键保护，确认对应断言确实转红。
6. 聚焦执行 `go test -count=1 -run '^TestP39' ./internal/tickets ./internal/adapters ./internal/console`；真实平台腿分别记录执行与跳过，不能合并算绿。

## 已知不可测点
- 错误注入和杀进程不能证明断电耐久；设备缓存、同目录原子替换及父目录屏障的保证需独立平台证明和断电验证。
- 原生锁与文件身份依赖对应平台/文件系统；mock、跳过或 replay 已有证明均不能替代预算后端证明，Windows 继续保持 `unproven` 边界。
