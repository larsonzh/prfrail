## B. 收益论证闸（核心）

实测收益（数字取自 `01-measurements.md`，本机 HEAD `9f3aea9`）：

- 单遍 3 作用域 = **285 s**（base 264 s / 92.6%）；本片 ④（2 遍）+ ⑨（2×3 遍）= 8 次 scope-run ≈ **760 s**，其中 base ≈ 704 s。
- 热遍全价 ≈ **7.7 s**（判据 7.01 + 键 ≈0.72）；**单切片可命中面 = ⑨ 第二遍的 3 个 scope-run**（⑨ 两遍间工作区快照冻结；④ 与 ⑨ 之间、以及跨片 HEAD 必变 ⇒ 不命中）。
  - test 纳入 ⇒ 节省 **3 × 88 ≈ 264 s/片**；
  - test 排除 ⇒ 节省 **3 × ~11 ≈ 33 s/片**（收益 −87%，gofmt+build+vet 实测仅 0.49+6.47+3.84 ≈ 10.8 s）。
- 键代价 ≈ 0.72 s/遍（不含内容哈希；实测时变更 7 路径，哈希开销可忽略）。

对照第三条路径（`--skip-base` 编排约定）：墙钟收益**完全等价**（7.7 s vs 7.01 s/热遍），零缓存、零键、零假绿；CI 现状已不重复支付 base。缓存的**增量价值**仅三处：

1. **报告完整性**：热遍报告仍含 base 四条读数，可满足台账验收「⑨ 两遍冷热、三作用域 TOTAL_FAIL=0、冷热逐字一致」——`--skip-base` 的第二遍不是全量，物理上无法产出该证据；
2. **机械保障替代操作纪律**：§6.3 原则「把『人肉记忆』换成『机械断言』」，`--skip-base` 依赖调用编排（人肉纪律），缓存是机械的；
3. 键不含 scope ⇒ 三作用域共享一条记录（见 C）。

新增风险：flake 假绿（仅本地、CI 独立兜底）；键实现复杂度；§5.1 例外集扩容的准则同步义务。

代价：`gate.js` 读路径包裹 + 新模块 `lib/baseCache.js`（注入式 exec/store，可测）+ selftest 新断言 + 附录 C 新块 + v1.78 双语镜像治理。

**结论：做**（条件 = D 裁定「test 纳入 + 只缓存 PASS」）。若停点 1 裁定「test 排除」⇒ 收益仅 33 s/片、增量价值只剩报告完整性 ⇒ 收益论证**不成立**，改按 P95 式**评估类闭环**收尾：零代码改动、准则不升版（v1.77 不变）、P88 建议 2 登记「已评估、收益不成立、不实施」、报告对同构收尾。

## C. 键设计草案（复用 C.0aj 句式）

- **`keyString`**（读缓存前**必须重算**，仅键不得持久化）：
  `base-v1 | HEAD | sha256(git status --porcelain=v1 -uall -z 原始输出) | sha256(未跟踪文件 排序(路径→磁盘内容sha256) 映射) | sha256(工作区已改跟踪文件 排序(路径→磁盘内容sha256) 映射) | go version | go env GOROOT GOOS GOARCH CGO_ENABLED GOFLAGS GOWORK`
  - **不含 scope**：`runBaseGates` 只读 `ctx.repoRoot` 的工作区（已核对 92–131 行），与作用域无关 ⇒ 三作用域共享单条目，正是「跨作用域」命名本意。
  - **未跟踪内容哈希在内**：`gofmt -l .` 与 `go build ./...` 都会读到未跟踪文件；`-uall` 含被忽略目录（如 `tmp/`），路径集合本身入键，内容哈希兜住「同名改内容」。
- **三反例必失效**：① 改已跟踪文件 ⇒ porcelain 摘要变；② 改未跟踪文件 ⇒ 内容映射摘要变；③ 改 `go.mod`/`go.sum`（已跟踪 ⇒ ① 覆盖）或切换工具链 / GOTOOLCHAIN / GOWORK ⇒ 工具链段变。
- **任何缓存异常一律 fail-open 回全量计算**：键不可算、条目缺失/畸形、读写抛错 ⇒ 冷跑路径原样执行，verdict / detail / 退出码与无缓存完全一致。命中路径不检测 `gofmt` 缺失（与 `--skip-base` 同面，由 CI Format 步与冷遍兜底）——**如实披露的已知边界**。
- **键计算代价** ≈ 0.72 s（实测三项 git/go 读取；**不含文件内容哈希，未验证大目录下的哈希开销**）。
- **超限放弃**：未跟踪路径数 > **200** 或累计字节 > **64 MB** ⇒ 本遍放弃缓存（fail-open）。**阈值为 ① 拟定的默认值，非实测推导**，由 ② 落常量、selftest 覆盖。
- **缓存目录**：`tmp/gates-cache/base/`（被 `.gitignore` 的 `/tmp/*` 覆盖；原子写 = 临时文件 + rename；条目名 = sha256(keyString).json；LRU 淘汰上限 **50**），并**同步修订 §5.1 例外集**：成员句增 `base/`、② 固定命令排除集增 `*\tmp\gates-cache\base\*`（③ 顶层排除不变）。
- **存储值 schema**：`{v:1, records:[{id:'base', verdict, label, detail} ×4]}`；`validValue` 严格校验形态（verdict ∈ {PASS,FAIL}、字符串字段），否则视为 miss。
- **冷热逐字一致**：命中/未命中均输出同一条 `INFO base-cache :: key <key12>`（**不写 hit/miss 字样**，否则冷热输出不逐字相等、破坏台账验收）；hit/miss 证据由 selftest（注入 store）与 ⑨ 计时承担。

## D. flake 政策两案对照（推荐由用户裁定）

- **案 1：纳入 test + 只缓存 PASS（推荐）**。收益 264 s/片。依据：FAIL 永不缓存 ⇒ 真实缺陷与冷遍 flake 红的行为与无缓存**完全一致**（冷遍红 → 热遍重算）；唯一新路径 = 「冷遍绿 + 热遍本应 flake 红 → 返回缓存绿」。该窗口 = 同机、同快照、相邻第二遍数分钟内（概率极低），且**后果仅限本地**——CI 每次冷跑真执行且不使用缓存，兜底存在。DR 史（DR-2~5 已修、DR-15/17 本机 AV/IO 单次）支持「残余 flake 低频」。残余风险在报告与条款如实披露。
- **案 2：排除 test（缓存 gofmt/build/vet 三条）**。零假绿、flake 史为零；但收益降至 33 s/片（−87%），触发 B 的「不做」分支。
- **两案共识**：绝不缓存 FAIL 结论；若案 1，⑨ 冷遍 FAIL ⇒ 不写缓存 ⇒ 热遍重算，两遍不一致时如实登记（与无缓存行为逐字一致）。

## E. 条款草案（落点 = §6.1「聚焦门禁定义」段之后、§6.2 之前）

> **base 结论缓存条款（v1.78，切片 P96 `GATES-BASE-CACHE`）**：§6.1 四条 base 门禁（gofmt / build / vet / test）的**结论**（PASS/FAIL + label + detail 摘要）可在跨进程缓存中复用，命中时报告仍含 base 四条读数。**绝不缓存任何 G1–G9 判据结论**；判据判定逻辑本体零改动，命中结论与冷跑逐字一致。
> - **键（读缓存前必须重算，仅键不得持久化）**：格式版本前缀 `base-v1` | HEAD | `git status --porcelain=v1 -uall -z` 输出摘要 | 未跟踪文件（路径→磁盘内容 sha256）排序映射摘要 | 工作区已改跟踪文件（路径→磁盘内容 sha256）排序映射摘要 | 工具链身份（`go version` + `go env GOROOT GOOS GOARCH CGO_ENABLED GOFLAGS GOWORK`）。键**不含** scope（base 四条只读工作区、与作用域无关）。
> - **三反例必失效**：① 修改任一已跟踪文件；② 修改任一未跟踪文件内容；③ 修改 `go.mod` / `go.sum` 或切换工具链（含 GOTOOLCHAIN / GOWORK）。任一成立 ⇒ 键必变 ⇒ 必重算。
> - **fail-open**：键不可算、条目缺失/畸形/不可读、写入失败、任何缓存异常 ⇒ 一律回全量计算，verdict / detail / 退出码与无缓存运行完全一致；缓存仅是优化，永不是第二真值源。
> - **flake 政策（停点 1 用户裁定，落定后填入）**：**[推荐] test 结论纳入缓存但仅缓存 PASS；FAIL 永不缓存**。缓存不得固化 FAIL 结论。
> - **有效性窗口**：仅同片 ⑨ 窗口内、键全等时有效；不主张跨片 / 跨机复用（HEAD 每片必变；CI 不使用缓存）。
> - **上限**：变更路径数或未跟踪内容字节超阈值 ⇒ 本遍放弃缓存（fail-open 回全量）。
> - **与 `--skip-base` 的关系**：`--skip-base` 时缓存不参与；缓存命中与 `--skip-base` 的差别 = 报告仍含 base 四行读数。
> - **缓存目录**：`tmp/gates-cache/base/`，纳入 §5.1 运行时缓存目录例外集（成员句与固定命令同步修订）；原子写、LRU 上限淘汰。
> - **升版义务**：键任一 segment 的语义变化、存储值 schema 变化、或四条 base 命令 / detail 口径变化 ⇒ 必须升级格式版本前缀，旧条目一律视为陈旧、不得复用。

可证伪性：键段与三反例有 selftest 断言（注入 exec/store，变异任一键输入 ⇒ 必重算）；fail-open 有注入式断言；「绝不缓存 G1–G9」由代码结构保证（缓存模块仅被 `runBaseGates` 引用，判据记录路径不含缓存）。

## F. 分级建议

**M 常规：⑦ = 1 终审 + 2 复审**（与台账披露口径一致，不升 1+3）。依据：① 判据判定逻辑本体零改动（G1–G9 逐字不动，缓存只包 base 读路径）；② fail-open 架构使错误单向（最坏 = 本地热遍假绿，绝无假红 / 丢判据）；③ C.0aj（G4b-CACHE）同构先例已按「非治理片、M 档、⑦ 按 §5.2 分档表」裁量，模板成熟；④ §7.5 高风险触发条件（R≥2 / 审查矛盾 / 原生反复失败）当前未出现。**升级条件**（停点 1 由用户裁）：若裁定「纳入 test」且要求条款含 flake 政策 ⇒ 仍 1+2，但 ⑦ 首轮输入必须含 DR 史摘录与「只缓存 PASS」断言链；若 ① 方案书被判定触及判据语义、或 §7.5 治理片字面口径被裁定适用 ⇒ 升 1+3。⑥ 必做（触 `gate.js` / `selftest.js`），台账已披露。
