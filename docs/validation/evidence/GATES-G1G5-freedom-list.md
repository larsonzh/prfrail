# GATES-G1G5 执行自由度清单（§1.7.3，⑥ 之后 ⑦ 之前落盘）

- **F-1 G1 的机械化边界取「可锚定子集」**：主控把「三处一致」收窄为四个可机械子判据 + 三项记录态收口，而不是强做全文语义比对；依据是台账本身已自陈状态闭集，且「标题陈旧但无完成记录」需片外事实。
- **F-2 G1 的键提取规则**：取单元格首段标识符（`A0` / `B3a` / `P10` / `GATES-EDGE-COVERAGE`），去反引号；两侧（CN / EN）用同一规则，避免双语键漂移。
- **F-3 G1(f) 的措辞集合**：取「进行中」/「In progress」/「待…定稿」/「awaiting finalisation」四种形态，直指 `GATES-EDGE-COVERAGE` 的实测缺陷。
- **F-4 G5 废除仓库外 JSON**：改为四字段机械派生，理由是原要求等于让主控自证；同时保留可选环境变量交叉比对，作为不阻断 CI 的加固。
- **F-5 G5(f) 的作用域条件**：仅在 index 作用域判「索引=磁盘」，tree / ci / range 记 `INFO`——clean checkout 无索引状态，强判会造成假红。
- **F-6 G5 的退出码口径**：三集合不等判 `FAIL`（退出码 1），用法 / 环境与外部 JSON 不一致判退出码 2；原 §6.3 字面把「三集合不等」也写作退出码 2，本片按「FAIL vs 用法错误」的分工统一并同步改文本。
- **F-7 G5(e) 的路径识别口径**：先按仓库根前缀集合（`docs/` `tools/` `examples/` `schemas/` `cmd/` `internal/` `harnesses/` `testdata/` `.github/`）识别，再补「单段根级工件 + 已知扩展名」（`README.md` / `go.mod` / `go.sum` 等）——⑥ 实测原口径对根级工件完全空判；补集时**加前后边界**（后边界含 ASCII 闭合括号），避免把 `go.modification` 一类正文误认成路径。代价：仍不识别非闭集根级文件名（如需扩展须逐项增补）。
- **F-8 G5(f) 的「脏」口径**：只判 porcelain 的 **Y 列**与 `??`，不判 X 列（已暂存）——index 作用域的正常状态就是「已暂存、工作区干净」；初版把已暂存判为脏，属实现缺陷而非自由度，已修正并留正夹具。
- **F-9 ⑦ 额度用满后的收口方式**：r3 的 1 条 Low 残差以**确定性自证**（探针读数 + T77 钉桩 + `SELFTEST 460/460` + 三作用域 `TOTAL_FAIL=0`）收口，未开第 4 读；这是额度约束下的自由度选择，**弱于独立复审**，已在本片报告 §4 如实登记。
- **F-10 G1(e) 无绑定行的呈现**：34 条历史完成记录的标题已被移除 ⇒ 无绑定；本片选择「(e) 只判 bound 行 + 另发 `G1(e-info)` INFO 记录」而不是判红，理由是历史片无法追溯补齐标题。
