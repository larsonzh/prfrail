# DIRECTIVE-TEMP-AUTH-LIMIT 执行自由度清单（§1.7.3，⑥ 之后 ⑦ 之前落盘）

本清单记录本片在**规则修订口径**上由主控自行做出的实质性选择；每条都落在用户起跑消息授权的范围内，未改范围与边界。

- **F-1 计数窗口的「归零重计」**：用户只要求「阈值体系须正式修订」，主控选择「窗口自该条款最近一次正式修订起算、修订后归零」——理由是计数只增不减会让规则修订永久背历史包袱，反而抑制修订；已在 ⑤ r1 被要求补「同款起跑消息不免计、不另起计数」以免归零被滥用。
- **F-2 例外类别取五类闭集**：主控自行归纳为「模型名单扩列 / 审查额度加轮 / 批量辅助越界 / 输入范围收窄或缺件豁免 / 跳环免测」，目的是让「同类」可机械判定；五类的划分与既有实例（OB-83、ADR-024、ADR-025、ADR-017/018）对得上。
- **F-3 真值源扩为「台账 + ADR 登记表」**：用户只要求修订阈值；主控按 ⑤ r1 的 M-2 把 ADR-only 实例纳入计数，并加「同一实例只计一次」防重复。
- **F-4 额度分层的具体数值**：用户只要求「审视」，主控提案 S 1+1 / M 1+2 / L·治理·高风险 1+3 并保留三条约束（收窄输入、不得中途升档、超限仍升级），依据是 ADR-025 记录的 7 次实例。
- **F-5 OB-92 的处置方式**：主控选择「不改写 ADR 历史裁定 + 加修订注记 + 在 §1.7.4 ⑤ 写落地句」，理由是保留裁决溯源；替代方案（直接改写 ADR-024 原文）会抹掉原始裁定。
- **F-6 ⑧c 时序的落点**：主控把「清理必须在记录落盘之后」写进 §5.1 的 ⑧c 说明（而不是 §1.5.1 的 tmp 生命周期），理由是它约束的是 ⑧c 环节而非目录生命周期；通用口径仍指向 §1.5.1。

以上均为**执行自由度**（错了需要改的是文本细节，不是范围 / 授权 / 预算）。
