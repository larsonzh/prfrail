二、B 的实现边界（r2 必须逐条写死，不得留白）
1) 预建调用点：装配层，`NewAgentRunnerReplayStoreForRun` 返回之后、首次派发之前。不得改 `NewAgentRunnerReplayStoreForRun` 签名；新增可选方法 `PrebuildReplaySlots(requestIDs []string) error`。
2) 预建输入：声明式 requestId 全集（`agentRunnerAssemblyRecords` 已校验的那一组）。调用方必须传全集，不得分批。
3) 预建失败语义：任一槽预建失败 ⇒ 整个 run fail-closed（store 不可用，不进入首次派发）；部分成功不得视为可用。已建成的空槽允许保留（幂等核验），但 run 必须停。
4) 重开语义：store 重开时对已存在槽做核验（magic + 长度 + payloadLen 合法性），不重建；槽缺失分两类——分配记录存在（预建全集已持久化）而槽缺失 = corruption fail-closed；从未预建的槽缺失 = 正常。
5) 适用边界：预建只对生产装配路径要求；包内测试、A2 dispatch 测试等非生产入口不强制预建（否则会大面积改测试）。r2 要写明这条边界，避免 ② 误伤测试。
6) 与 A7 的偏离如实登记：A7 原文「bootstrap 类程序预建」，本方案是「装配层在 store 构造后调用预建」。A2 条款必须写清「谁调用、何时调用、失败语义」，并加一句「本实现较 A7 原文的偏离点 = 预建由装配层触发而非 bootstrap 程序内部；该偏离不改 C6 的结构性优势（目录项仍在首次派发前一次性建立）」。
7) 预建全集的持久化：是否需要在 replay root 里落一份「预建全集」记录（用于重开时机械检出「应存在而缺失」）？r2 必须给结论。若落，格式与发布路径要写清；若不落，缺失槽识别只能靠 R+C 绑定，与 High 1 的异常路径合并处置。
