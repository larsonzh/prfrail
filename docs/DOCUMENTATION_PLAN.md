## 4. 低成本模型执行卡

每个 T 任务开始前，由实施者在会话中填入真实值，不创建充满占位符的任务文件：

```text
任务: Txxx；REQ: 列明；AT: 列明；授权范围: 具体路径
输入: 分域权威小节 + 必要的建议书来源段落 + 当前测试；禁止事项: 复制任务行
当前假设: 一条可证伪原因；最小检查: 一条实际命令
预算: 本轮时长/调用数/费用上限；未授权则无付费调用
完成证据: 命令/cwd/退出码/用例数/产物摘要/未验证项
```

一次只改能由最小检查验证的切片；失败先分析首错，禁止递归全仓扫描、重复粘贴长日志、凭空增加框架。上下文保留任务契约/父摘要/已确认决策/最新失败，不带整段聊天历史。token 用量缺失标估算；不得为节省 token 丢掉安全约束。

升级给维护者：契约歧义、权限扩大、需改非授权路径、同错误两次无新证据、预算耗尽、不可恢复状态。交接只提供改动、验证和下一步，不反复描述整个项目。

## 5. 文档审查规则

中文保留原名，英文采用 `_EN`，首部互链；REQ/AT/T/ADR/SEC 和 wire 标识完全一致；所有表中的数字代表需求/任务计数而非产品完成率。两版同一变更一起提交评审，不能只更新摘要译本。冲突按第 1 节定位对应中文权威文档修订，再同步英文、Schema 和引用方。

区分事实、提案、测量与计划；未实跑例子写“规划”。本地链接只指向已存在文件，未来路径用代码文字并说明拟建。文档 UTF-8 BOM+LF；机器 canonical/wire 不继承 Markdown 编码。冻结片段由独立 validator/示例执行检查；本轮文字契约不冒充机器验证。

验收留痕：本轮检查由终端执行；后续 T003 将文档/契约检查收敛到可入库工具，T017 接 CI。每阶段保留报告和未决项，不把 checkbox 一次全部勾选。追踪 checkpoint 只证明计划映射，不是人工批准或实现验收。

产品完整性增补从 [需求 §8](PRODUCT_REQUIREMENTS.md#8-产品完整性评审2026-09-06) 进入；项目建议书 §19 保留来源追踪，对应契约 §9、架构 §6、安全 §6、操作 §8、ADR-008、P1.7 与 AT-16–AT-21。保留 28 个 REQ 和 12 对文档；PC-01–PC-06 的映射必须与主映射取并集。S1 exit 文档增加上手、交付包、授权撤销、费用说明、备份/恢复/卸载和 SBOM；S2/S3 增强仅列候选，不冒充首版已支持。
